# 服务器外观资产（图标 + 多 Banner）

服务器（Guild）级展示资产 REST API 与事件契约。双认证平面同形挂载：
后台 `/api/v1`（aud=admin，系统管理员享受全服短路）与用户端 `/gapi/v1`
（aud=client，**无 SystemAdmin 短路**，全部走标准 RBAC）。

## 1. 存储与 URL 约定

- 二进制文件与用户头像/服务器图标同约定：`DATA_DIR/profile/` 目录，
  经 **`/public-assets/profile/{name}`** 公开访问（平面中立前缀，无需登录）。
- 文件名含 guild ID 与纳秒版本号（不可枚举、不可变），响应头
  `Cache-Control: public, max-age=31536000, immutable`，可放心长缓存。
- **不复用消息附件（Attachment）表**：附件 GC 会清理未绑定消息的记录（24h），
  且消息保留策略/软删清理连带删附件；banner/图标随服存续、由服管显式增删，
  混用会被消息清理误删，故独立建 `GuildBanner` 表（图标沿用 `Guild.icon_url` 列）。

## 2. 校验与上限

| 项 | 规则 |
|----|------|
| 类型 | PNG / JPEG / WebP / GIF / **MP4**，服务端**魔数嗅探**（`http.DetectContentType` + MP4 `ftyp` 盒），不信 Content-Type |
| 大小 | ≤ 8 MiB（独立于每服消息附件上限 25MB——展示资产无需大文件，独立且更小） |
| banner 数量 | 每服默认 10 张；部署级环境变量 `GUILD_BANNER_MAX_COUNT` 全局可调 |
| 尺寸/比例 | 不强制（客户端裁剪） |
| MP4 播放 | 客户端 / Web 默认静音循环；悬浮到图标或当前 banner 时才播放声音；多 banner 以轮播展示（图/视频可混排） |

## 3. REST API

写操作均需 `MANAGE_GUILD`（bit 5，覆盖「修改服务器设置、图标」）或后台平面系统管理员；
无权限 → `403 MISSING_PERMISSION`；非成员读写一律 `404 NOT_FOUND`（防扫频）。
上传为 multipart 直传（字段名 `file`），与服务器图标/语音包音频既有模式一致
（小文件展示资产，不走附件 presign 二段式）。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/guilds/{gid}/icon` | 设置/更换图标（multipart `file`）→ 200 `{url, guild}` |
| DELETE | `/guilds/{gid}/icon` | 清除图标 → 200 guild |
| GET | `/guilds/{gid}/banners` | banner 列表（成员可读）→ 200 `{guild_id, banners, limit}` |
| POST | `/guilds/{gid}/banners` | 新增 banner（追加到末尾）→ 201 `{banner, banners}`；超上限 400 `BANNER_LIMIT_REACHED` |
| PATCH | `/guilds/{gid}/banners` | 重排序，body `{"banner_ids": [id...]}` **全量有序数组** → 200 `{banners}`；不恰好覆盖全部/重复 → 400 `BANNER_IDS_MISMATCH` |
| DELETE | `/guilds/{gid}/banners/{bannerID}` | 删除（归属校验：他服资产等同不存在 404）→ 200 `{banners}` |

- banner 对象：`{id, guild_id, url, position, created_at, updated_at}`，
  `position` 0 起连续升序（删除后自动重编号）。
- 重排序选**全量有序 ID 数组**而非 `[{id, position}]` 增量：banner 数量小（≤10）
  且客户端总是整条拖拽，全量提交天然原子、无位置空洞与重复歧义
  （角色排序用增量是因为角色可只动局部层级）。
- 读取投影：`GET /guilds/{gid}`（详情）与 `GET /guilds`（后台列表）、
  `GET /gapi/v1/users/@me/guilds`（用户端列表）均附带
  `icon_url`（Guild 字段）与 `banners: [{id, url, position, ...}]`。

## 4. Gateway 事件

图标/banner 变更沿用 **`GUILD_UPDATE`**（按 guild 广播）：

```json
{
  "guild": { "...": "Guild 全量（含 icon_url）" },
  "banners": [ { "id": "...", "url": "...", "position": 0 } ],
  "event_at": "2026-07-21T00:00:00Z"
}
```

`banners` 字段仅在 banner 增删/排序触发的 GUILD_UPDATE 中携带（最新全量列表，
客户端整体替换）；其他 guild 变更事件省略该字段（收到后可按需重拉
`GET /guilds/{gid}/banners`）。

## 5. 审计

`guild.icon_update` / `guild.icon_remove` / `guild.banner_add` /
`guild.banner_remove` / `guild.banner_reorder`（internal/audit 既有风格）。
