## 1. 服务端状态机（Newt-Server/internal/voice/migration.go）

- MigrationJob 持久化于 `voice_migration_jobs`（09 §5.4 全字段 +
  `from_session_id`：PREPARE 首次尝试快照迁出侧旧 sid，供 CLEANUP 按 sid 精确摘除）。
- 五段：`QUEUED → MIGRATING_PREPARE → MIGRATING_CONNECT → MIGRATING_CUTOVER →
  MIGRATING_CLEANUP → DONE`；失败进 `MIGRATING_FAILED` 后换目标重试
  （快速重试 3 次，之后指数退避排队重试，永不「回大厅」）。
- 段超时（可配，默认 K.2 建议值）：PREPARE 2s / CONNECT 8s / CUTOVER 2s / CLEANUP 3s。
  CONNECT 超时**自动推进**（09 M.4：客户端无响应不阻塞，Gateway 重连后靠
  VoiceState 对齐）；客户端 ack（`POST /voice/migrations/:id/ack`）提前推进并记
  `connected_at`。
- 并发控制：同 `user_id + guild_id` 仅一个活跃 job；优先级
  死亡(40) > 分区(30) > Drain(20) > 手动(15) > 过载(10)，高优先级抢占取消低优先级，
  低优先级请求被在途高优先级 job 吸收合并。
- 触发接线：
  - **死亡（硬判死）**：心跳 5s×3 判死（15 BI.1）→ `internal.NODE_DOWN` → 按
    （源节点, 房间）分批 `MIGRATE_BATCH`：先为批代表打分选 `batch_target`（10 U.2），
    同批全部预置该目标（J.5 同房收敛），容量不满足时 PREPARE 重打分兜底；
  - **死亡（BI.3 提前判死，15 §5）**：`internal/sfucontrol` 聚合两类独立提前信号——
    ① 级联邻居 EdgeDown 指控（EdgeStatus 上报者为边一端且自身心跳健康时，构成对
    另一端的指控，origin 按上报者去重）；② 客户端侧 ICE/连接失败上报（新端点
    `POST /voice/rtt` 同级的 `POST /voice/ice-failed`，双前缀挂载，origin 按用户去重，
    单用户 5s 节流）；SFU 自报 `PARTICIPANT_ICE_FAILED` RoomEvent 计入弱信号
    （整类恒 1 个 origin，`self_ice`）。组合规则：**≥2 个独立信号源 + ≥1 次心跳丢失**
    → 提前判死（无需等满 3 次）；判死权威仍仅 Server（BI.4）。监控扫描 1s 一轮；
    阈值可配：`SFU_EARLY_DEATH_ENABLED`（默认开）/ `_MIN_SOURCES`（2）/
    `_MIN_HEARTBEAT_MISSES`（1）/ `_SIGNAL_TTL`（30s）。节点重连（Attach）清空旧信号；
  - **分区（09 §3.3 升级接线）**：同一叶边 60s 内 ≥3 次 EdgeDown（重发边集修复无效）
    → 对该叶节点上本房用户触发 MIGRATE_LEAF（`reason=PARTITION`，批量目标收敛）；
    升级后该边冷却 5 分钟防震荡（`internal/voice/partition.go`）；
  - **Drain**：admin `POST /admin/sfu/nodes/:id/drain` → 状态 DRAINING（调度硬拒）
    → `internal.NODE_DRAINING` → 立即批量迁出；60s 后若仍有会话挂在该节点
    （且节点仍 DRAINING），重新触发批量迁移兜底（I.6 硬迁语义）；
  - **手动**：`POST /admin/voice/migrations`（系统管全权 / 服管 MANAGE_GUILD 仅本服）；
  - **过载（09 I.3–I.5 已实装，默认关）**：`VOICE_OVERLOAD_AUTO_MIGRATE=true` 开启后，
    节点 CPU（默认 ≥85%）/ 出口带宽（默认不启用，`VOICE_OVERLOAD_BANDWIDTH_MBPS`）/
    并发占用（默认 ≥90% max_users）任一维度**超阈值持续 T=30s** → 触发 MIGRATE_BATCH，
    每轮 ≤ 该节点会话 15% 且 ≤50 人（取更严；15% 取整为 0 时放行 1 人），轮后冷却
    60s 再评估；对象挑选：听众/非台上优先（N.1，接 `StageSpeaker`），同级内进房时间
    短优先（N.2 的「当前未在说话」信号 Server 侧暂无低成本来源，留待 speaking 上报接线）。
- **refresh-token 迁移窗口（M4 遗留 bug 修复）**：迁移 PREPARE 后 VoiceState 的
  `voice_session_id` 已是新 sid 而 `node_id` 仍指旧节点。此窗口内
  `POST /voice/refresh-token`：CONNECT/CUTOVER/CLEANUP（目标已定）→ **按 job 的
  to_node 签发**（新 sid 会话在目标节点，刷新服务于双 PC 中的新连接；响应新增
  `node_id` 字段）；QUEUED/PREPARE/FAILED（目标未定）→ `425 MIGRATION_IN_PROGRESS`，
  客户端等 `VOICE_SERVER_UPDATE`（自带绑定新节点的全新 token）。取舍：不一律报错，
  因 CONNECT 窗口可达数秒，期间续签仍应可用。
- 根死切根（08 §7.1 完整实现）：冻图（编排互斥锁内）→ electAnchor（人最多 →
  负载低 → region → node_id）→ 升 epoch → SetAnchorLease → 重建星型边整体下发
  → **逐边等关键 EdgeUp**（步骤 5，单边超时仅记录，PREPARE 的 ensureCascade 再次
  以边就绪为门槛兜底）→ 返回后由迁移引擎对原根用户跑状态机（步骤 6–7）→
  CLEANUP 阶段空边回收（步骤 8）。
  - 边界：房内**全部**用户都在死根上时无存活候选，无法选举——此时清空旧租约与
    旧边，让迁移目标节点以「首人进房」语义成为新 anchor（epoch 从 1 重新计数，
    旧图无任何存活涉边节点，无冲突）。
- 舞台/caps 保留（09 专项 1 注意 3 + 11 AF.1）：CONNECT 签发的新 token 按 Server
  权威状态重算 caps；CLEANUP 完成后发布 `internal.CAPS_DIRTY(reason=migration)`
  驱动舞台等模块向新节点重放 caps。
- 审计（O.1）：`voice.migration.created / completed / failed` 三类审计 +
  job 行内 `prepared_at / connected_at / cutover_at / completed_at / attempt /
  tried_nodes / last_error` 全程留痕；用户可见文案默认模糊（O.2，事件里只有
  「线路优化中」类文案与 migration_id，无节点/原因技术细节；管理端查审计与 job 表）。

## 2. 控制通道指令扩展（proto/owlsfu/v1/control.proto）

### 2.1 `MigrateParticipants` 增加 `phase`（M4 实装，Ack 不再 UNIMPLEMENTED）

```proto
message MigrateParticipants {
  string migration_id = 1;
  string room_id = 2;
  repeated string session_ids = 3;  // 迁出侧旧会话 sid（15 BJ.3 按 sid 精确定位）
  string to_node_id = 4;
  Phase phase = 5;                  // MARK | EXECUTE；未指定按 EXECUTE（向后兼容）
}
```

- **MARK**（CONNECT 阶段 → 源节点）：SFU 按 sid 标记会话「迁出中」，CUTOVER 前
  继续正常服务；仅观测与关闭语义用。源节点已死（DEATH 触发）时下发失败被忽略。
- **EXECUTE**（CLEANUP 阶段 → 源节点）：SFU 按 sid RemoveParticipant，客户端收到
  `closed{code=MIGRATED}`（区别于 SESSION_REVOKED，不清除重连意愿）；sid 不在线
  幂等跳过。按 sid（而非 uid）摘除保证绝不误伤同 uid 在新节点的新会话（15 BJ.2）。

### 2.2 `Drain` 增加 `cancel`

```proto
message Drain {
  int64 deadline_unix_ms = 1; // 09 I.6 硬迁时限（提示性；硬迁由 Server 兜底强推）
  bool cancel = 2;            // true = 取消排空（admin undrain），恢复接受新会话
}
```

M4 前 undrain 只改 Server 侧状态，SFU 的 draining 标志残留导致新会话被
`NODE_DRAINING` 拒绝；现在 undrain 会下发 `Drain{cancel=true}` 同步复位。

## 3. Gateway 事件（JSON，S→C 定向推送给当事用户）

对齐 05 §11；载荷为 `DISPATCH` 帧的 `d` 字段。

### `VOICE_MIGRATING`（进入迁移，驱动 UI 与双 PC 准备）

```json
{
  "migration_id": "<uuid>",
  "guild_id": "<uuid>",
  "channel_id": "<uuid>",
  "message": "线路优化中，语音将自动切换"
}
```

`message` 默认模糊文案（09 O.2）；不携带节点 ID / reason 码等技术细节。

### `VOICE_SERVER_UPDATE`（新节点接入信息 + token；迁移时带 migration_id）

```json
{
  "guild_id": "<uuid>",
  "channel_id": "<uuid>",
  "node_id": "<uuid>",
  "room_id": "<uuid>",
  "sfu_endpoint": "wss://…/ws",
  "token": "<Media Token, nid=新节点, sid=新会话>",
  "caps": ["join", "publish_audio", "subscribe_audio"],
  "session_id": "<新 sid>",
  "expires_at": "<RFC3339>",
  "migration_id": "<uuid，进房辅助路径不带>"
}
```

### `VOICE_MIGRATED`（迁移成功收尾，可清 UI）

```json
{
  "migration_id": "<uuid>",
  "guild_id": "<uuid>",
  "channel_id": "<uuid>",
  "node_id": "<uuid>"
}
```

## 4. 客户端双 PC 热切（09 M.3；参考实现 Newt-SFU/cmd/loadbot servermode.go）

```text
收 VOICE_MIGRATING            → 进入切换态（UI 可提示）
收 VOICE_SERVER_UPDATE        → 用新 endpoint+token 建第二个 PC（旧 PC 继续收发）
新 PC state=connected（CUTOVER）→ 发送原子切到新 PC（旧停发）；
                                POST /voice/migrations/:id/ack（失败可忽略：
                                CONNECT 8s 超时会自动推进）
新 PC 首个下行 RTP             → 打点 mute_gap_ms = 新 PC 首包 − 旧 PC 末包；拆旧 PC
（源节点侧旧会话同时被 MigrateParticipants EXECUTE 摘除，双保险）
```

- CUTOVER 语义 = 客户端在新 PC 连通即切（09 §7.2 表格中「可由 VOICE_SERVER_UPDATE
  携带」的备选未采用——事件无需额外字段，减少协议面）。
- 双会话窗口内新旧 PC 属同一 uid 的两个 sid，SFU 侧互不干扰（15 BJ.2）。

## 5. loadbot Server 模式（e2e 载体）

```text
loadbot --server-url http://… --username U --password P [--signup] \
        --guild GID --channel CID [--rtt-report "node:5,node:400"] --duration 90s
```

登录（/gapi/v1）→ 可选 RTT 上报（引导调度落点）→ voice/join → Gateway WS
（IDENTIFY/HEARTBEAT/DISPATCH）→ 建 PC 推收音频 → 自动处理迁移事件（§4）。
退出统计行含 `mute_gap_ms`（最近一次热切静音窗口）与 `mute_gaps_ms`（全部）。

## 6. 端到端验收

脚本：[`scripts/e2e-migration.sh`](../../scripts/e2e-migration.sh)
（独立数据库 `owl_e2e_mig_<ts>`、独立端口，可重复运行）。三场景：

| 场景 | 动作 | 断言 | 实测静音窗口 |
|------|------|------|--------------|
| 叶死 | kill -9 非 anchor 节点 | BI.3 提前判死生效、用户自动迁到存活节点、音频恢复、mute_gap < **10s** | ~6.2s（EdgeDown 指控 + 客户端 ice-failed 上报 + 1 次心跳丢失 → 提前判死 ≈5s + 迁移 1–2s） |
| Drain | admin drain | 秒级主动迁走、mute_gap < 5s | ~0–20ms（双收窗口重叠） |
| 根死 | kill -9 anchor 节点 | lease 换根 + epoch+1 + 原根用户迁移 + 双方恢复互听、mute_gap < 25s | ~4.9s（提前判死同样生效） |

三场景均在迁移后断言双方 `recv` 持续增长（迁移后 caps 重放：publish/subscribe
仍生效）；叶死场景另断言 loadbot 已发出 `ice_failed_report`（BI.3 客户端侧信号）。

## 6.1 观测指标（09 §11）

Server 侧 Prometheus（默认注册表；`METRICS_ADDRESS` 非空时经独立监听暴露
`/metrics`，仅应绑定内网/本机，如 `127.0.0.1:9091`）：

| 指标 | 类型 | 说明 |
|------|------|------|
| `owl_voice_migrations_created_total{reason}` | counter | 创建的迁移 job 数 |
| `owl_voice_migrations_completed_total{reason}` | counter | 成功（DONE）数；与 failed_attempts 组合得成功率 |
| `owl_voice_migrations_canceled_total{reason}` | counter | 取消数（离房/切频道/被抢占） |
| `owl_voice_migration_failed_attempts_total{reason}` | counter | 尝试失败次数（随后换目标重试） |
| `owl_voice_migration_retries_total{reason}` | counter | FAILED → QUEUED 归位重试次数 |
| `owl_voice_migration_preemptions_total` | counter | 高优先级抢占次数（K.4/K.5） |
| `owl_voice_migration_phase_seconds{phase}` | histogram | prepare / connect / cutover_cleanup 阶段耗时 |
| `owl_voice_migration_total_seconds{reason}` | histogram | job 创建 → DONE 总时长（P50/P99 由直方图导出） |
| `owl_voice_migration_mute_gap_seconds{reason}` | histogram | 静音窗口近似：job 创建（判死/触发）→ `connected_at`（客户端 ack 连上新节点）；客户端未 ack（超时自动推进）时无样本 |

SFU 侧既有 `/metrics`（信令端口）已含每边 RTT gauge
`owlsfu_cascade_edge_rtt_ms{room,peer_node}`（级联 ping 5s 周期更新）及
边级 bytes/packets、剪枝轨数、迁出会话数等（M3/M4 已实装，无缺口）。

## 7. 与设计文档的偏离点

| 项 | 偏离 | 理由 |
|----|------|------|
| ~~09 §3.3 分区触发~~ | **已实装**：叶边 60s 内 ≥3 次 EdgeDown → MIGRATE_LEAF（reason=PARTITION）+ 5 分钟冷却 | 根故障仍走 `degraded` 标记 + 判死切根（分区两侧双活由 Server 权威裁决） |
| ~~15 BI.3 提前判死组合规则~~ | **已实装**：≥2 独立信号源 + ≥1 次心跳丢失（阈值可配，默认开） | 叶死静音窗口从 ~18s 压缩到 ~6s |
| ~~09 I.3–I.5 过载自动迁移~~ | **已实装**（默认关，`VOICE_OVERLOAD_AUTO_MIGRATE` 可开） | 阈值初值（CPU 85% / 并发 90% / T=30s / 冷却 60s）待压测标定；带宽维度默认不启用（无出口容量基线） |
| 09 N.2「当前未在说话」 | 过载对象挑选未接 speaking 信号（仅 N.1 非台上优先 + 进房时间短） | Server 侧无低成本实时 speaking 来源；留待 SFU speaking 聚合上报接线 |
| 08 §7.1 步骤 5 | 关键边 EdgeUp 单边超时不中断切根（记录 + 由 PREPARE 的 ensureCascade 兜底） | 切根持编排锁，硬阻塞会放大故障半径；迁移 PREPARE 仍以边就绪为门槛，语义不变 |
| 根死且房内无存活节点 | 清空旧租约/边，迁移目标以首人语义重建 anchor（epoch 从 1 计） | 无候选可选举；旧图无存活涉边节点，epoch 重新计数无「旧图复活」风险 |
