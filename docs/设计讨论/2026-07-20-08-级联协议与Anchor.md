## 1. 目标与已定约束

| 目标 | 说明 |
|------|------|
| 同语音频道多节点 | 用户按地域进入不同 SFU，**池内级联** 组成同一逻辑房 |
| 拓扑 | **有根星型为默认**；最大深度 **2**；**禁止全连接** |
| 故障 | 节点挂 → 用户自动接最近存活节点；**允许短暂静音**；禁止回大厅手进 |
| 编排权威 | **Owl-Server** 算图、发边、授租约；**Owl-SFU** 只执行 |

---

## 2. 标识与房间模型（A）

| 编号 | 定稿 |
|------|------|
| **A.1** | `logical_room_id = channel_id`（或与 channel 稳定 1:1 映射，全局唯一） |
| **A.2** | 节点内：`local_room = (logical_room_id @ node_id)`，**仅对内**；客户端 / 对外 API **只暴露 logical** |
| **A.3** | **级联 peer 不计入** 语音频道 200 人硬顶（基础设施，非用户） |

### 2.1 概念关系

```text
Guild 节点池: { N1, N2, N3, ... }   // 调度与级联不得出池

Voice Channel (channel_id)
    └── logical_room_id  (= channel_id)
            ├── local @ N1  ← 用户 Ua, Ub
            ├── local @ N2  ← 用户 Uc
            ├── local @ N3  ← 用户 Ud, Ue
            └── cascade edges (树/星，Server 下发)
                    e.g. N2 → N1(anchor), N3 → N1(anchor)
```

## 3. Anchor（B）

| 编号 | 定稿 |
|------|------|
| **B.1** | 粒度：**每个逻辑语音房一个 Anchor**（非整服一个） |
| **B.2** | 选举：优先 **当前房内用户数最多** 的节点；并列时用稳定 tie-break（建议：负载更低 → region 偏好 → `node_id` 字典序） |
| **B.3** | **首个进房用户所在节点 = 初始 Anchor**；随后可 **rebalance 换根** |
| **B.4** | **运行中允许换根**（优化分布、过载、运维、根故障） |
| **B.5** | 权威：**Server 租约**——`anchor_node_id + epoch + lease_expire`；无有效租约不得自称根 |

### 3.1 租约（逻辑）

```text
AnchorLease {
  logical_room_id
  anchor_node_id
  epoch: uint64          // 单调递增；更大 epoch 覆盖旧图
  lease_expire_at
  issued_by: server_id
}
```

- SFU 仅在 `epoch` 匹配且租约未过期时，按图转发。  
- 换根 / 重构图时 **先升 epoch**，旧边作废。  
- 心跳续约由 Server 驱动或 SFU 申请续约（实现可选，语义：Server 可随时吊销）。

## 4. 拓扑构建（C）

| 编号 | 定稿 |
|------|------|
| **C.1** | 默认：**有根星型**（非根节点直接挂到 Anchor） |
| **C.2** | **最大深度 2**（允许 region hub：叶 → hub → anchor） |
| **C.3** | 建边权威：**仅 Server** 下发边集；SFU **禁止** 私自互联 |
| **C.4** | 边未就绪：客户端 **短静音等边**，再满血订阅/出声 |
| **C.5** | Server 保证 **树/DAG**；SFU **丢弃** 非父/子边预期来源的回环包（防御） |

### 4.1 深度约定

```text
depth 0: Anchor
depth 1: 直连 Anchor 的节点 或 region hub
depth 2: 挂在 hub 下的叶节点
depth ≥ 3: 禁止
```

何时上二级 hub（实现策略，可配置）：

- 默认星型（深度 1 边）。  
- 当某 region 叶节点数或中继流量超过阈值时，Server 在该 region 选 hub，叶改挂 hub（深度 2）。

### 4.2 边模型

```text
CascadeEdge {
  logical_room_id
  epoch
  parent_node_id
  child_node_id
  // 媒体/控制连接参数由双方 mTLS 会话协商
}
```

完整图 = 某 `epoch` 下的边集合 + AnchorLease。  
**替换图必须整体切换 epoch**，禁止半新半旧边长期并存（切换窗口内可双缓冲，见 §7）。

### 4.3 新用户进房挂边（顺序）

```text
1. Server: RBAC + 选节点 N（池内，RTT/region/容量）
2. Server: EnsureLocalRoom(N, logical_room)
3. 若 N 非 anchor 且 N 尚无到根的路径:
     Server: 计算边（N→anchor 或 N→hub→anchor）
     SetCascadeEdges(epoch, edges…)
4. 等待边就绪（SFU 上报 EdgeUp）或超时失败/换节点
5. 签发 Media Token（nid=N, rid=logical_room, caps…）
6. 客户端 ICE；边就绪前可连信令但 **短静音**；EdgeUp 后开订/开发
```

## 5. 媒体转发与订阅剪枝（D）

| 编号 | 定稿 |
|------|------|
| **D.1** | **选路 RTP 转发**，不混流、不转码（默认） |
| **D.2** | 同节点用户：节点内本地 SFU 转发，**不经级联** |
| **D.3** | 跨节点：沿树上传/下行到目标枝（子→父→其它子） |
| **D.4** | **订阅剪枝**：若某子树 **无人订阅** 某 speaker track，则 **不向该枝推送** |
| **D.5** | **首期**：客户端静音某用户 = **上报取消订阅** → SFU/级联 **停该路**（省带宽，非仅本地静音） |

### 5.1 订阅集合

```text
对每个 (listener_user, speaker_user):
  需要一条订阅边（逻辑上）
聚合到节点级:
  NodeWant[child][speaker_track] = OR(本地听众订阅, 子树需要)
向上通报给 parent，形成剪枝
```

- 台上最多 50 路上行时，剪枝与取消订阅是级联可扩展的关键。  
- 重新取消静音 = 再订阅 → 级联恢复该 track。

### 5.2 屏幕共享（预留）

- 同模型：`publish_screen` track 沿树转发 + 剪枝。  
- 动态配额由 Server 控制是否允许 publish（07）；级联层只转发已允许的 track。

## 6. 控制面与级联认证（E）

### 6.1 建议 RPC / 指令（逻辑名）

| 指令 | 方向 | 作用 |
|------|------|------|
| `EnsureLogicalRoom` | S→SFU | 节点上创建/保活 local room |
| `SetAnchorLease` | S→SFU | 下发/吊销根租约 |
| `SetCascadeEdges` | S→SFU | 下发某 epoch 边集（全量或 diff，实现自定，语义以 epoch 为准） |
| `EdgeStatus` | SFU→S | EdgeUp / EdgeDown / RTT / 丢包 |
| `UpdateSubscriptions` | S→SFU 或 SFU 本地+汇总 | 订阅变更（客户端经 Server 或经 SFU 再上报 Server） |
| `MigrateParticipants` | S→SFU | 与热迁移衔接：迁出/迁入用户 |
| `CloseLogicalRoom` | S→SFU | 房间无人且无边时回收 |

**开音条件（E.3）**：到 anchor 路径上 **边就绪之后** 才允许满血 subscribe/publish（之前短静音）。

### 6.2 级联认证（E.4）

| 项 | 定稿 |
|----|------|
| 方式 | 节点间 **mTLS**（复用节点证书身份）和/或 **池内短期 cascade credential**（Server 派生、绑定 `logical_room_id + epoch + edge`） |
| 禁止 | 无认证的裸互信转发 |

推荐组合：

1. 控制/级联信令会话：节点 **mTLS**（已有 enrollment）。  
2. 媒体或旁路会话：可选 **cascade token**（短 TTL，防持证节点被滥用拉流）。

### 6.3 级联不出池

建边两端 `node_id` 必须 ∈ 该 Guild 的 **节点池**；Server 校验失败则拒发边。

## 7. 换根与 Anchor 故障（F）

### 7.1 切根顺序（F.2 定稿）

```text
1. 冻结旧 epoch（停止接受旧图变更；可标记 MIGRATING）
2. 选择新 Anchor（人最多等规则；排除死亡/Drain 节点）
3. 升 epoch，SetAnchorLease(新根)
4. SetCascadeEdges：存活节点挂到新根（或新 hub 树，深≤2）
5. 等待关键 EdgeUp
6. MigrateParticipants：原根（及不可用节点）上用户 → 最近存活节点
7. 客户端双 PC 热切；短静音窗口
8. 打开订阅；回收旧边与旧 local room
```

### 7.2 叶节点死亡

- **不换根**（除非死者即根）。  
- 删除相关边；用户迁到最近存活节点；必要时补边。

### 7.3 Rebalance 换根（非故障）

- 允许；应 **限频**（如每房 N 分钟最多一次）避免震荡。  
- 同样走 §7.1 顺序；UI 可提示「线路切换中」。

## 8. 客户端（G）

| 编号 | 定稿 |
|------|------|
| **G.1** | **不暴露** anchor；只下发：目标 `node` 接入信息、token、`migration_id` / epoch 相关元数据 |
| **G.2** | UI **可提示**「切换中 / 线路优化中」 |
| **G.3** | **双 PC 热切**：新建 PeerConnection 就绪后再切收发，再拆旧连接，缩短静音 |

### 8.1 事件（与 05/07 对齐）

| 事件 | 用途 |
|------|------|
| `VOICE_SERVER_UPDATE` | 换节点 endpoint + token |
| `VOICE_MIGRATING`（建议） | 进入切换态，驱动 UI 与双 PC |
| `VOICE_STATE_UPDATE` | 进房/离房/台上等 |
| 订阅变更 | 客户端静音/取消静音 → API 或 DC → Server/SFU **UpdateSubscriptions** |

## 9. 端到端时序（摘要）

### 9.1 首人进房

```text
Client→Server join → 选 N1 → N1 成 anchor（lease epoch=1）
→ 无边 → token → Client↔N1 媒体
```

### 9.2 异地第二人

```text
Client2→Server join → 选 N2（近）
→ EnsureRoom N2 → SetCascadeEdges N2→N1
→ EdgeUp → token → Client2↔N2
→ 订阅：N2 向 N1 拉/推所需 track（剪枝）
```

### 9.3 客户端静音某人（D.5）

```text
Client unmute UI off → Unsubscribe(speaker)
→ 本节点更新 NodeWant → 向上剪枝
→ 级联停止该 speaker 送往本枝
```

### 9.4 Anchor 宕机

```text
心跳失败 → §7.1 切根 → 用户热切 → 恢复
```

---

## 10. 失败与超时

| 场景 | 行为 |
|------|------|
| 边建立超时 | 换备用父节点或换用户入点节点；失败则 join 503/重试，**不**掉到大厅半残状态 |
| 租约过期未续 | SFU 停止跨节点转发并告警；Server 重发或切根 |
| 环路包 | SFU 丢弃 + 指标告警 |
| 池外建边请求 | Server 拒绝 |

## 12. 本轮结论汇总

| # | 结论 |
|---|------|
| 1 | `logical_room_id` 对齐 channel；local 仅内部；级联不占 200 人 |
| 2 | 每房一 Anchor；首人即根；人最多选举；Server 租约 + epoch |
| 3 | 默认真有根星型，深≤2；仅 Server 建边；边就绪后开音 |
| 4 | 选路 RTP + 订阅剪枝；**首期**静音=取消订阅 |
| 5 | 级联 mTLS 和/或短期 cascade credential；不出池 |
| 6 | 切根：冻 epoch→新根→挂边→迁用户；双 PC 热切；UI 可提示 |
