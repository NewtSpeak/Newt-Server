## 1. 容量与语音子频道形态（议题 1）

### 1.1 「1000 人」口径（修订）

| 项 | 定稿 |
|----|------|
| 单 SFU 节点目标 | **约 1000 并发用户**（媒体会话已建立） |
| 业务含义 | 千人级在线负载由 **多个子频道** 分担；用户在各频道内发言/发消息 |
| 非含义 | **不是** 单频道 1000 人全员全双工互听 |

### 1.2 单语音子频道人数

| 档位 | 值 | 行为 |
|------|-----|------|
| **软上限** | **50** | 常规全双工语音（房内可互相听，策略可全订或按实现优化） |
| **硬上限** | **200** | 超过拒绝进入（除非产品另开例外，首期无） |
| **大房门槛** | **约 100+ 或超过软上限进入「大房策略」** | 必须 **舞台模式 + 听讲模式**（见下） |

> 实现备注：软上限 50 用于 UX 提示/默认推荐；**允许** 配置或业务上开到 51–200，但一旦进入大房区间，**强制** 舞台/听讲模型，禁止百人全员互订音频。

### 1.3 舞台模式 + 听讲模式

| 角色 | 能力 |
|------|------|
| **发言者（台上）** | 可 publish 音频（及后续视频/屏幕位）；人数 **软 20 / 硬 50**（以 [07](./2026-07-20-07-专项1至5定稿决议.md) 为准） |
| **听众（听讲）** | 默认可 subscribe 台上音频；**不可** 随意上麦 |
| **麦序** | 支持申请上麦；**子频道管理员 / 协管** 可 **实时抱上麦序**（同意/抱麦/抱下） |

### 1.4 协管员

- 子频道管理员可设置 **协管员**（channel-scoped 管理身份，细节落在 RBAC/角色或频道专属角色）。
- 协管至少具备：麦序管理、抱上/抱下、（可选）频道内 mute 等，**权限节点可配置**，不得超越服级授权上限。

### 1.5 对 SFU 的含义

- 大房：订阅图为 **听众 → 最多 20 路上行**，带宽近似线性，可支撑硬顶 200。
- 小房（≤50）：保持现有全双工模型。
- Media caps 需区分：`publish_audio`（台上）vs 仅 `subscribe_audio`（听众）+ `request_to_speak` 等信令。

## 5. 节点管控、级联与热迁移（议题 5）— **重大修订**

> **废止** 01/04/05 中「首期不做级联/热迁移、接受短中断重连」的表述。

### 5.1 服级节点池（创建/管理服务器时）

控制面（Owl-Server）在 **创建/配置「服务器」(Guild)** 时支持：

| 能力 | 说明 |
|------|------|
| **管控可用 SFU 节点** | 从已 enrollment 且在线的节点中，为该服选择 **允许使用的节点集合（节点池）** |
| **跨境/跨区分配** | 可将 **特定 region / 跨境节点** 划入某服的池（合规、延迟、专线等） |
| **调度范围** | 该服下语音频道 **只** 在所属节点池内调度；池外节点不可见 |

### 5.2 SFU 级联（Cascade）

| 项 | 定稿 |
|----|------|
| 需求 | **支持** SFU 之间媒体/会话级联（跨节点同逻辑房间或房间片段） |
| 目的 | 单频道用户可能落在池内不同物理节点时仍组成同一语音体验；跨区扩展 |
| 权威 | 拓扑与切换由 **Owl-Server 编排**；SFU 执行转发边 |

> 专项设计（拓扑算法、环路避免、带宽成本）另文：`docs/设计讨论` 后续「SFU 级联与热迁移」专题。

### 5.3 热迁移（Hot Migration）

| 项 | 定稿 |
|----|------|
| 故障策略 | 节点挂掉时，**不接受**「用户手动重连的短中断」作为合格体验 |
| 目标行为 | 故障节点上的用户 **自动** 迁到：**同服节点池内、地理/网络最近、且资源占用最低** 的 SFU |
| 编排者 | Owl-Server 根据心跳/健康与容量指标选目标，下发迁移；客户端 + SFU 配合 **无缝或准无缝** 切换（ICE 重绑/快速重入 + 级联兜底，细节专题定） |
| SLA 方向 | 以 **自动完成迁移** 为成功标准；允许极短媒体间隙，但产品叙事为 **不接受需用户感知的短中断重连流程** |

### 5.4 与「同频道单节点」旧假设的关系

- 旧首期假设「一语音频道固定单节点」**降级为优化默认**，不再是硬约束。
- 在池内可多节点承载 + 级联；迁移后 room 绑定更新。

## 6. 多维限制 / 禁言（议题 6）— 已定稿

**废止**「单一 timeout 只 mask 全局说话」的过粗模型；改为可组合的 **限制维度**：

### 6.1 维度矩阵

| 作用域 | 文字：观看 | 文字：发言 | 语音：收听 | 语音：发言 |
|--------|------------|------------|------------|------------|
| **单个文字子频道** | ✓ | ✓ | — | — |
| **单个语音子频道** | — | — | ✓ | ✓ |
| **整个服务器 · 全部文字频道** | ✓ | ✓ | — | — |
| **整个服务器 · 全部语音频道** | — | — | ✓ | ✓ |

- 「禁止观看」文字频 ≈ 无 `VIEW_CHANNEL` / 强制不可见（与权限计算叠加时 **限制优先收紧**）。
- 「禁止收听」语音 ≈ 不可 `CONNECT` 或进房后 deafen 级限制（实现二选一，专题定，语义是 **不能听**）。
- 「禁止发言」文字/语音分别对应 `SEND_MESSAGES` / `SPEAK` 的强制剥夺。

### 6.2 与 RBAC 的关系

- **限制（Restriction / Sanction）** 是叠加在最终权限上的 **否定层**（类似 timeout，但可多维、多对象）。
- 计算顺序建议：RBAC 得出 bits → **再应用生效中的限制 mask** → 得到有效权限。
- `ADMINISTRATOR` 是否免疫限制：默认 **可被系统管/更高权限施加**；服管互不能乱 ban 同级（层级规则沿用角色 position）。

### 6.3 数据模型方向（逻辑）

```text
Restriction {
  target_user_id
  scope: GUILD_ALL_TEXT | GUILD_ALL_VOICE | CHANNEL
  channel_id?:  // CHANNEL 时
  deny: { view_text?, send_text?, listen_voice?, speak_voice? }
  expires_at?
  reason?, actor_id
}
```

## 7. 权限层级与覆盖（议题 7 + 9 角色部分）

### 7.1 三级权威

```text
系统管理员（平台）
    │  可覆盖 / 管控任意「服务器」的配置与权限策略
    ▼
服务器管理员（Guild Admin / ADMINISTRATOR / 所有者）
    │  可覆盖该服内角色与频道权限
    ▼
子频道覆盖 + 协管（Channel Overwrite / 协管权限）
```

| 角色 | 能力要点 |
|------|----------|
| **系统管理员** | 平台级；可接管服配置、禁用服、指定服节点池、覆盖服管设置 |
| **服务器管理员** | 自定义本服 **角色（RBAC）**、权限节点、默认与覆盖；可覆盖子频道策略 |
| **子频道管理员 / 协管** | 在被授予的权限节点内管理本频道（麦序、部分 mute 等） |

### 7.2 自定义角色与访问范围（议题 9）

- 系统管 + 服管可定义角色：**权限节点集合** + **访问范围**。
- 访问范围必须支持 **按子频道** 细化（允许/拒绝列表或 overwrite），比「仅服务器 bitmask」更细。
- `@everyone` 默认：**可看、可发消息、可连麦、可说话**（开放社区默认）。

### 7.3 谁能改频道 overwrite（议题 7 在操作层的落地）

| 操作者 | 定稿 |
|--------|------|
| 系统管理员 | 可改任意服、任意频道覆盖（审计必记） |
| 服务器管理员 / 具备足够服级权限者 | 可改本服频道覆盖（受角色层级与「不可授予超过自身权限」约束） |
| 仅 `MANAGE_CHANNELS` 无管理角色权 | **不足以** 单独改敏感覆盖（除非服管显式把节点授给该角色）—— 以 **可配置权限节点** 为准，而非写死单一 bit |

## 9. 进房 API 与入场语音包（议题 10）— 已定稿

| 路径 | 角色 |
|------|------|
| **主路径** | `POST /voice/join` → 返回 Media Token、节点提示、caps 等 |
| **辅助路径** | Gateway **`VOICE_SERVER_UPDATE`**（Discord 风格推送），便于客户端统一状态机与重连/迁移 |
| **状态广播** | `VOICE_STATE_UPDATE` 等 |

### 9.1 入场语音包（Voice Pack / 进服音效）

| 项 | 定稿 |
|----|------|
| 需求 | 用户 **进入服务器**（或进入指定场景，产品可配置）时，向 **相关范围内用户** 播放 **指定音频** |
| 范围（待产品微调，默认建议） | 默认同服在线成员或同语音频道成员可听；需可配置以免骚扰 |
| 实现方向 | **非** 把文件经 SFU 当长期轨道；倾向：控制面下发事件 + **短音频 URL/资源 ID**，客户端本地播放；或短时 SFU 注入（后期） |
| 权限 | 谁可配置语音包、谁可使用稀有音效 → 纳入角色权限节点 / 资产系统 |

与 `VOICE_SERVER_UPDATE` 并行：进服/进房事件可携带 `voice_pack_id` 或独立 `VOICE_PACK_PLAY` 事件。
