## 1. 目标

| 目标 | 说明 |
|------|------|
| 双模式 | 语音频道：`FREE_DISCUSSION`（自由讨论）/ `STAGE`（舞台） |
| 防爆带宽 | **>50 人强制 STAGE**；超额 **自动禁说** + FIFO 释放 |
| 可控上台 | 台上 **默认 20、硬顶 50**；申请队列 + 抱上/抱下；大房禁止自由上麦 |
| 状态权威 | **Owl-Server** 维护角色/队列；SFU 只认 caps |

## 2. 频道模式（Y）

### 2.1 枚举

```text
VoiceChannelMode = FREE_DISCUSSION | STAGE
```

### 2.2 配置字段（逻辑）

```text
VoiceChannelStageConfig {
  mode
  max_speakers: 1..50        // 默认 20
  request_to_speak_enabled: bool
  co_moderator_ids: []
  // 可选：协管是否可改 mode
  allow_co_mod_change_mode: bool  // 默认 true，可关
}
```

### 2.3 谁可改模式（Y.2）

| 角色 | 能力 |
|------|------|
| 服管 / 具备频道管理或舞台管理权限节点 | 可改 |
| **协管** | **默认可改本频道模式**；频道/服配置 **`allow_co_mod_change_mode` 可关** |

### 2.4 模式切换

| 切换 | 定稿 |
|------|------|
| **FREE → STAGE（Y.3）** | 当前可说话人数若 > `max_speakers`：按 **开麦/成为可说状态更久者优先留台**，其余变 `AUDIENCE`（可提示） |
| **STAGE → FREE（Y.4）** | 清除申请队列；若 **当前人数 > 50 → 禁止切回 FREE** |
| **人数 ≤50（Y.5）** | **不自动** 改回 FREE；保持 STAGE 直至管理员/协管（若允许）修改 |

### 2.5 >50 强制 STAGE（Z.2）

| 项 | 定稿 |
|----|------|
| 条件 | 频道内 connected（VoiceState 在频道内，含 pending）**> 50** |
| 动作 | **强制 `mode = STAGE`** + 提示升级/已进入大房规则 |
| 随后 | 按 STAGE 规则运行；若仍有超额可说需求，走容量自动禁说（§3） |

人数统计：**以 Server VoiceState 在该语音频道内为准**（Z.7）。

## 3. 容量自动禁说队列（Z）

> 用于：大房下避免「人人可 publish」；与 Restriction、server_mute **分来源**。

| 编号 | 定稿 |
|------|------|
| **Z.1** | 阈值：connected **> 50** |
| **Z.3** | **第 51 人及之后**（按 **进房顺序**）进入容量限制：可听、**不可说/不可占 SPEAKER 除非被抱上** |
| **Z.4** | 来源标记：`CAPACITY_QUEUE` |
| **Z.5** | 有人离开释放名额：**FIFO**——**最早被容量禁说者优先解除** |
| **Z.6** | 被容量禁说者 **自动进入申请队列尾部**（可再被抱上） |

### 3.1 与「前 50 人」

- 进房序前 50：不因 CAPACITY_QUEUE 自动禁说。  
- 但若 `max_speakers` < 当前想说话人数，仍受 **台上名额** 约束（STAGE 下须 SPEAKER 槽）。  
- FREE 在 >50 时会被强制改 STAGE，再套用台上规则。

### 3.2 释放算法（摘要）

```text
on UserLeave(channel):
  recompute capacity_muted set by join_order
  // 保持「最多 50 人不受 CAPACITY_QUEUE 禁说」的窗口
  // 对仍 muted 且在申请队者维持队列；新解除 muted 者若需上麦仍走申请/抱麦
```

「不受 CAPACITY_QUEUE」≠ 自动成为 SPEAKER；STAGE 下上台仍要名额 + 抱麦/原 SPEAKER 身份。

## 4. 台上名额（AA）

| 编号 | 定稿 |
|------|------|
| **AA.1** | `max_speakers ∈ [1, 50]`，**默认 20**；**硬顶 50 不可配超** |
| **AA.2** | 配置在 21–50：允许，UI 可警告超过推荐软限 20 |
| **AA.3** | 台上已满时抱上：**拒绝**（须先抱下他人） |
| **AA.4** | 角色：`SPEAKER` / `AUDIENCE`（+ 队列态 `QUEUED`） |
| **AA.5** | FREE：无 SPEAKER 槽位概念；有 RBAC `SPEAK` 即可 publish（仍受 Restriction 等） |

## 5. 申请队列与抱麦（AB）

### 5.1 队列

```text
StageQueueEntry {
  user_id
  requested_at
  source: USER_APPLY | CAPACITY_QUEUE | ADMIN
}
```

| 编号 | 定稿 |
|------|------|
| **AB.1** | FIFO |
| **AB.2** | 可申请：在频道内、非 SPEAKER、未被禁申请的限制、且 `request_to_speak_enabled` |
| **AB.3** | 关申请：仅抱麦；申请 API 返回关闭 |
| **AB.7** | 队列长度上限 **100**；满则拒绝新申请 |
| **AB.8** | 重复申请幂等，保持原位 |
| **AB.9** | 管理/协管 **可直抱**，不必经队列 |

### 5.2 抱上 / 抱下 / 下麦

| 操作 | 定稿 |
|------|------|
| **抱上（AB.4）** | 占 SPEAKER 槽；caps 给 `publish_audio`；移出队列 |
| **抱下（AB.5）** | → AUDIENCE；停 publish；**不回队列** |
| **用户主动下麦（AB.6）** | → AUDIENCE；释放槽 |

满额抱上 → **拒绝**（AA.3）。

## 6. 用户子状态机（AC）

### 6.1 三态（AC.1）— STAGE 模式

```text
AUDIENCE
  │ apply（若开启）
  ▼
QUEUED
  │ bring-up / 直抱
  ▼
SPEAKER
  │ bring-down / self off-stage / 超时掉席
  ▼
AUDIENCE
```

附加标志（可与 AUDIENCE/QUEUED 并存）：

- `capacity_muted`（来源 `CAPACITY_QUEUE`）  
- `server_mute` / Restriction 禁说（**AD.5 与抱下分离**）

### 6.2 FREE 模式

- 无 QUEUED/SPEAKER 槽；有效「能说」= RBAC + Restriction + mute。  
- >50 强制进入 STAGE 后切换到 §6.1。

### 6.3 超时与断线

| 编号 | 定稿 |
|------|------|
| **AC.2** | 申请队列条目 **30 分钟** 无处理可过期移除（用户可重新申请） |
| **AC.3** | SPEAKER/QUEUED **断线后 60s** 保留席位；超时释放槽位/队位，变 AUDIENCE |

重连 60s 内：恢复原 stage 角色并重发 caps（配合 09 迁移则 **AF.1 保留状态**）。

## 7. 权限、Restriction 与 caps（AD）

### 7.1 上台条件（AD.1）

须同时大致满足：

1. 在语音频道内（CONNECT 路径合法）  
2. 无 Restriction/禁说导致不可讲  
3. STAGE 下获得 **SPEAKER** 槽（抱上或模式切换时保留）  
4. 非 capacity 禁说，或已被抱上解除有效禁说  

### 7.2 协管权限节点（AD.3，最小集）

| 节点 | 说明 |
|------|------|
| `STAGE_BRING_UP` | 抱上 |
| `STAGE_BRING_DOWN` | 抱下 |
| `STAGE_MANAGE_QUEUE` | 拒队、清队、排序（若做） |
| `STAGE_CHANGE_MODE` | 改 FREE/STAGE（受 Y.2 开关约束） |

可由 **服角色模板** 授予；频道协管列表任命 + 节点交集生效。

### 7.3 Caps 投影（AD.4）

| 状态 | publish_audio | subscribe |
|------|---------------|-----------|
| SPEAKER（且未 server_mute/Restriction 禁说） | ✓ | ✓ |
| AUDIENCE / QUEUED | ✗ | ✓（再受客户端取消订阅） |
| capacity_muted 未上台 | ✗ | ✓ |

### 7.4 Mute vs 抱下（AD.5）

| 操作 | 效果 |
|------|------|
| **server_mute / 禁说** | 可仍为 SPEAKER 占槽，但 **不可 publish** |
| **抱下** | 失去 SPEAKER 槽，变 AUDIENCE |

API 与 UI 必须分开，避免「静音变下麦」。

## 8. API 与事件（AE）

### 8.1 REST（逻辑）

| 接口 | 作用 |
|------|------|
| `PATCH /channels/{id}/voice-stage` | mode、max_speakers、request_to_speak_enabled、协管开关等 |
| `POST /channels/{id}/stage/apply` | 申请上麦 |
| `DELETE /channels/{id}/stage/apply` | 取消申请 |
| `POST /channels/{id}/stage/bring-up` | `{ user_id }` |
| `POST /channels/{id}/stage/bring-down` | `{ user_id }` |
| `POST /channels/{id}/stage/self-leave` | 主动下麦 |

### 8.2 Gateway

| 事件 | 内容 |
|------|------|
| `VOICE_STATE_UPDATE` | 含 `stage_role`: AUDIENCE\|QUEUED\|SPEAKER，及 mute 标志 |
| `STAGE_QUEUE_UPDATE` | 队列变更；**全员简表**（AE.1：id/昵称/序），管理可见扩展字段 |
| `STAGE_INSTANCE_UPDATE` 或频道配置更新 | mode、max_speakers、开关 |

### 8.3 主咖（AE.2）

- **不做服务端主咖位**；听众通过客户端静音/取消订阅自选听谁（08 D.5）。

## 10. 端到端场景摘要

### 10.1 小房讲座（≤50，手动 STAGE）

```text
管理设 STAGE, max_speakers=5, 开申请
用户 apply → QUEUED → 协管 bring-up → SPEAKER
听众取消订阅某人 → SFU 剪枝（08）
```

### 10.2 人数冲过 50

```text
第 51 人进房 → 强制 mode=STAGE → 提示
第 51+ 打 capacity_muted + 入申请队尾
管理可 bring-up（若有槽）
有人离开 → FIFO 解除最早 capacity_muted
```

### 10.3 试图 >50 切回 FREE

```text
拒绝；错误码如 STAGE_REQUIRED_BY_CAPACITY
```

### 10.4 满 20 槽再抱

```text
拒绝；须先 bring-down
```

## 12. 结论汇总

| # | 结论 |
|---|------|
| 1 | FREE / STAGE；协管改模式默认可关 |
| 2 | FREE→STAGE 开麦久者优先留台；>50 禁止回 FREE；不自动回 FREE |
| 3 | >50 强制 STAGE；容量禁说 FIFO 解除；自动入申请队 |
| 4 | max_speakers 默认 20、硬顶 50；满额拒绝抱上 |
| 5 | 申请 FIFO 上限 100；抱下不回队；可直抱 |
| 6 | AUDIENCE / QUEUED / SPEAKER；申请 30min 过期；断线 60s 留席 |
| 7 | mute 与抱下分离；队列全员简表；无服务端主咖 |
| 8 | 迁移保留舞台状态并重发 caps |
