## 1. 目标与范围

### 1.1 目标

一次定稿完整「贴图 / 小表情」子系统，覆盖：

1. **创建与归属**：用户账号级贴图包；可选创建仅本服可用的服独属包  
2. **双 kind**：小表情（emote，可输入框连发）与贴图（sticker，点选发送、禁止图文混排）  
3. **发现与收藏**：消息内点击预览；整包引用 Install；单条复制 Copy  
4. **发送与反应**：库内才可发消息；小表情与贴图均可作 reaction（贴图缩放对齐）  
5. **治理**：服管 ban 包；Web 后台全局 ban / 删包 / 删条；作者软删与 180 天恢复  

### 1.2 与 Discord / KOOK 的差异（产品定位）

| 点 | Discord | 本文 |
|----|---------|------|
| 谁创建 | 主要服管上传 | **用户个人创建**，服管只治理 |
| 短码 | 用户/服设 shortcode | **禁止手设**；系统按内容 hash 生成 mark |
| 发现 | 较弱 | **点消息反查整包** + `allow_browse_full` |
| 收藏 | 偏 Nitro/服同步 | **整包引用 + 单条复制** |
| 可用性 | 在服即可用（Nitro 等） | **必须在用户贴图库可用集合内才能发消息** |

### 1.3 不在本次范围

- Unicode 标准 emoji 选择器与 jumbo 规则（仍按 Owl-Desktop 05 FR-23/24，与本专项并存）  
- 表情包商店 / 付费 / 审核工单流（服管可 ban；可选「发布需审核」为后续扩展，首期不做强制审核流）  
- 客户端离线打包导出

## 2. 核心概念

| 术语 | 说明 |
|------|------|
| **Pack（贴图包）** | 一组同 kind 的表情容器；有所有者、scope、浏览/收藏策略 |
| **Item（表情项）** | 包内一张图；有 `item_id`、内容 hash、asset |
| **kind** | `emote`（小表情）或 `sticker`（贴图）；**创建后锁定，包内禁止混装** |
| **scope** | `account`（账号级，可跨服）或 `guild`（服独属，仅本服） |
| **Install** | 整包加入贴图库 = **引用**，随原包变化 |
| **Copy** | 单条复制到自己的包 = **独立副本**，不随原作者 |
| **mark** | 由内容 hash 自动生成的系统标志；全站规范 hash 唯一（A1） |
| **可用集合** | 用户可用来**发送消息**的 item 集合（见 §5.1） |

## 3. 数据模型

### 3.1 `sticker_packs`

```text
sticker_packs (
  id                snowflake PK,
  owner_user_id     snowflake NOT NULL,
  scope             enum('account','guild') NOT NULL,
  guild_id          snowflake NULL,          -- scope=guild 时必填
  kind              enum('emote','sticker') NOT NULL,  -- 创建后不可改
  name              text NOT NULL,
  description       text NULL,
  cover_item_id     snowflake NULL,
  allow_browse_full boolean NOT NULL DEFAULT true,
  status            enum(
                      'active',
                      'soft_deleted',           -- 作者软删，180 天内可恢复
                      'soft_deleted_expired',   -- 超过 180 天，作者不可恢复，数据仍在
                      'globally_banned',
                      'purged'                  -- 管理员硬删终态
                    ) NOT NULL DEFAULT 'active',
  soft_deleted_at   timestamptz NULL,
  restore_deadline  timestamptz NULL,        -- soft_deleted_at + 180d
  created_at, updated_at
)

CONSTRAINT guild_scope_requires_guild
  CHECK (scope <> 'guild' OR guild_id IS NOT NULL)
CONSTRAINT account_scope_no_guild
  CHECK (scope <> 'account' OR guild_id IS NULL)
```

### 3.2 `sticker_items`

```text
sticker_items (
  id                snowflake PK,
  pack_id           snowflake NOT NULL REFERENCES sticker_packs,
  kind              enum('emote','sticker') NOT NULL,  -- 冗余，必须 == pack.kind
  name              text NULL,               -- 展示名，可搜索；非 shortcode
  content_hash      text NOT NULL,           -- 规范化文件内容 hash（如 sha256 hex）
  mark              text NOT NULL,           -- 系统生成，如 'e_' || left(hash,12)；全站与 hash 一一对应
  asset_id          snowflake NOT NULL,     -- 指向 blob；A1 去重可共享
  width, height     int NOT NULL,
  animated          boolean NOT NULL DEFAULT false,
  source_item_id    snowflake NULL,         -- Copy 溯源
  source_pack_id    snowflake NULL,
  sort_order        int NOT NULL DEFAULT 0,
  status            enum('active','purged') NOT NULL DEFAULT 'active',
  created_at, updated_at
)

-- 同 pack 内 sort 可重复，列表以 sort_order, id 稳定排序
-- kind 与 pack.kind 由服务端写入时强制一致
```

### 3.3 资源去重（A1）

```text
sticker_assets (
  id            snowflake PK,
  content_hash  text NOT NULL UNIQUE,   -- 规范 hash 全局唯一
  storage_key   text NOT NULL,
  mime          text NOT NULL,
  size_bytes    bigint NOT NULL,
  width, height int NOT NULL,
  animated      boolean NOT NULL,
  ref_count     int NOT NULL DEFAULT 0, -- item 引用计数；硬删 item 时递减
  created_at
)
```

| # | 规则 |
|---|------|
| **A1.1** | 上传时对规范化字节流计算 `content_hash`；命中则复用 `sticker_assets` 行，新建 `sticker_items` 指向同一 `asset_id`。 |
| **A1.2** | `mark` 由服务端根据 hash 生成，**拒绝客户端自造 mark/shortcode**。 |
| **A1.3** | 消息与反应存储 **`item_id`**（权威）；可冗余 `content_hash`/`mark` 便于渲染降级。 |
| **A1.4** | 管理员硬删 item 时 `ref_count--`；`ref_count=0` 且无消息/反应快照依赖时方可 GC blob（实现可延迟 GC）。 |

### 3.4 `user_pack_library`（整包引用）

```text
user_pack_library (
  user_id       snowflake NOT NULL,
  pack_id       snowflake NOT NULL,
  status        enum('active','hidden') NOT NULL DEFAULT 'active',
  -- active: 在贴图库可见可用
  -- hidden: 作者软删导致的软隐藏；作者恢复后自动回 active，无需重装
  installed_at  timestamptz NOT NULL,
  sort_order    int NOT NULL DEFAULT 0,
  PRIMARY KEY (user_id, pack_id)
)
```

### 3.5 服级 / 全局 ban

```text
guild_pack_bans (
  guild_id, pack_id,
  banned_by, reason, created_at,
  PRIMARY KEY (guild_id, pack_id)
)

-- 全局 ban 用 packs.status = globally_banned，或独立 global_pack_bans 表（二选一，实现时定）
```

### 3.6 反应与消息中的引用

- 反应：在既有 reaction 模型上扩展，自定义表情用 `item_id`（及可选 hash 快照）作 key 的一部分。  
- 历史消息：存发送时的 `item_id`；渲染优先解析当前 item/asset，失败则占位。

## 4. 包规则

### 4.1 创建

| # | 规则 |
|---|------|
| **P.1** | 任意登录用户默认可创建账号级包；服独属包需为该服成员。 |
| **P.2** | 创建时必选 `kind` 与 `scope`；**此后不可改 kind**；`scope` 不可从 guild 改为 account 以「洗白」独属内容（若需跨服，应对 account 包重新上传/Copy 规则内操作——服独属禁止 Copy，见 B3）。 |
| **P.3** | `allow_browse_full` 默认 `true`，所有者可改。 |
| **P.4** | 服可配置「是否允许成员创建服独属包」（可选开关，默认允许）；账号级包不受此开关影响。 |

### 4.2 `allow_browse_full` 与收藏矩阵

| scope | allow_browse_full | 预览完整列表 | Install 引用 | 单条 Copy |
|-------|-------------------|--------------|--------------|-----------|
| account | true | ✅ | ✅ | ✅ |
| account | false | ❌（仅当前点开的一项 + 包基础信息） | ❌ | ✅ |
| guild | true | ✅ | ✅（仅本服上下文） | ❌ |
| guild | false | ❌ | ❌ | ❌ |

| # | 规则 |
|---|------|
| **P.5** | `allow_browse_full=false`：**禁止**整包 Install；account 包仍允许单条 Copy。 |
| **P.6（B3）** | `scope=guild`：**永远禁止**单条 Copy；他人仅能通过本服 Install 引用获取。 |
| **P.7** | `guild + allow_browse_full=false`：他人无法入库 → **仅所有者（及创建时已满足条件者）在本服使用**；创建 UI 必须提示。 |

### 4.3 跨服

| # | 规则 |
|---|------|
| **P.8** | `scope=account` 的自有包与已 Install 引用包：**允许跨服发送**（仍受目标服 ban、频道发言权约束）。 |
| **P.9** | `scope=guild`：**仅** `current_guild_id == pack.guild_id` 时可出现在可用集合并发送。 |
| **P.10** | 不依赖 `USE_EXTERNAL_EMOJIS` 限制跨服账号包；该权限位可保留给后续更细策略或废弃（实现首期按 P.8）。 |

## 5. 贴图库与发送鉴权

### 5.1 可用集合（发送消息）

用户 U 的可用 item 集合：

```text
ItemsIn(自建且 status=active 的 packs)
∪ ItemsIn(library 中 status=active 的 Install packs
           且 pack.status=active
           且 scope 允许当前上下文
           且 当前服未 ban 该 pack
           且 非 globally_banned / purged)
```

| # | 规则 |
|---|------|
| **L.1** | **不在可用集合 → 拒绝作为消息内容发送**（含篡改请求、转发节点）。 |
| **L.2** | 历史消息中的 item **仍可渲染**（不要求查看者在库中）。 |
| **L.3** | 点击消息中的表情可打开 Pack Preview（受 `allow_browse_full` 与 pack 状态约束）。 |
| **L.4** | 单条 Copy 的目标必须是 U **拥有**且 **kind 相同** 的 active 包；计入目标包 100 张配额。 |
| **L.5** | Install 仅当：`allow_browse_full && pack.status=active && 未全局 ban && （guild 包则当前在该服）`。 |

### 5.2 小表情输入

| # | 规则 |
|---|------|
| **E.1** | 禁止用户设置 shortcode；选择器 / 搜索按 **展示名、最近使用、mark** 检索。 |
| **E.2** | 输入框可插入多个小表情节点；序列化为自定义节点（见 §8）。 |
| **E.3** | 不可用「打字伪造 mark」绕过库校验；服务端只认 `item_id` 且校验可用集合。 |

### 5.3 贴图消息

| # | 规则 |
|---|------|
| **S.1** | 贴图为独立消息形态；**禁止与正文、附件、小表情图文混排**。 |
| **S.2** | 一条消息 **恰好一张** 贴图（首期硬约束）。 |
| **S.3** | 发送路径：选择器点选 → 直接发消息（或确认后发）；校验可用集合与 scope。 |

## 6. 删除、恢复与隐藏（C）

### 6.1 作者软删整包

| # | 规则 |
|---|------|
| **C.1** | 作者删除整包 = **软删除**：`status=soft_deleted`，写 `soft_deleted_at`、`restore_deadline=soft_deleted_at+180d`。 |
| **C.2** | **180 天内**作者可调用恢复 → `status=active`，清空软删时间戳。 |
| **C.3** | **超过 180 天**：`status=soft_deleted_expired`；**作者不可恢复**；系统 **不自动硬删**。 |
| **C.4** | **仅管理员**可 `purged` 硬删（整包或单条）。 |
| **C.5** | 软删期间：所有 Install 行 `status=hidden`（**软清空展示**，不删行）。 |
| **C.6** | 作者恢复后：所有该 pack 的 Install 行自动 `status=active`，安装者无需重装。 |
| **C.7** | 软删 / expired 期间：**禁止** 新 Install、**禁止** 单条 Copy 入库、**禁止** 从选择器新发该包 item。 |
| **C.8** | **历史消息始终保留展示**（软删不撕 CDN；资源仍在）。 |

### 6.2 状态机

```text
active
  ├─ 作者软删 ──────────► soft_deleted ──(作者恢复)──► active
  │                            │
  │                            └─(满 180 天)──► soft_deleted_expired
  ├─ 全局 ban ──────────► globally_banned（可解 ban 回 active，策略由后台定）
  └─ 管理员硬删 ────────► purged

Install 行：active ◄──► hidden（随作者软删/恢复）
服级 ban：guild_pack_bans 独立，不改 pack.status
```

### 6.3 Copy 与源包生命周期

| # | 规则 |
|---|------|
| **C.9** | 已 Copy 出的 item **不随**源作者软删/改包而变化。 |
| **C.10** | 源 pack 软删后 **不可再** 从源 Copy；已存在副本不受影响。 |
| **C.11** | 管理员硬删源 item 时：副本有独立 `item_id` 与（可能共享的）asset；`ref_count` 保护共享 blob。 |

## 7. 反应（D + 产品第 9 条）

| # | 规则 |
|---|------|
| **R.1** | **小表情与贴图均可**作为 reaction 标记。 |
| **R.2** | 贴图作反应时，UI **强制缩放**到与 Unicode emoji / 小表情反应 **同一视觉尺寸**（建议 16–20 CSS px 高）。 |
| **R.3** | 已有 reaction **计数保留**。 |
| **R.4** | 作者软删 pack、用户卸装（Remove Install）、item 对发送不可用时：已有反应上的表情 **仍然可见**，且 **仍允许继续添加/切换同一 item 的反应**。 |
| **R.5** | **发消息**与 **反应** 分鉴权：发送走 §5.1 可用集合；反应在 item 未 `purged` 且资源可解析时放行（软删仍放行）。 |
| **R.6** | 管理员 `purged` 后：尽量显示；无法解析则占位，计数仍可保留至清理策略另定。 |
| **R.7** | 添加反应仍需频道 `ADD_REACTIONS` 权限（02 bit 6）。 |

实现建议：反应表存 `item_id` + `content_hash`/`asset_id` 快照，避免仅依赖「当前是否在库」。

## 8. 消息载荷

### 8.1 小表情节点（富文本 / 结构化 content）

```json
{
  "type": "custom_emote",
  "item_id": "1234567890",
  "pack_id": "0987654321",
  "mark": "e_a1b2c3d4e5f6",
  "animated": false
}
```

- 一条消息可含多个 `custom_emote` 节点，可与文本混排。  
- 服务端发送校验：每个 `item_id` ∈ 发送者可用集合；`kind=emote`。  

### 8.2 贴图消息

```json
{
  "type": "sticker",
  "content": "",
  "sticker_items": [
    { "item_id": "111", "pack_id": "222", "mark": "e_..." }
  ]
}
```

| # | 规则 |
|---|------|
| **M.1** | `type=sticker` 时 `content` 必须为空（或忽略非空并 400）。 |
| **M.2** | `sticker_items` 长度必须为 1。 |
| **M.3** | item 必须 `kind=sticker` 且 ∈ 可用集合。 |

## 9. 配额

| 对象 | 默认 | 说明 |
|------|------|------|
| Install 他人包 | **不限制** | 仅受存储/性能保护性上限时可另加系统级熔断 |
| 用户自建 pack 数 | **25** | emote + sticker **合计**；软限制；后台可调全局默认与 per-user |
| 每自建包 item 数 | **100** | 含 Copy 进入的条目；后台可调 |
| 单文件大小 / MIME | 实现时定默认 | 建议 WebP/PNG/GIF/APNG；动图有上限；后台可调 |

超限返回明确错误码（如 `PACK_LIMIT` / `ITEM_LIMIT`）。

## 10. 权限与治理

### 10.1 RBAC

| 位 / 能力 | 用途 |
|-----------|------|
| 发言相关权限 | 发送含小表情的消息、发送贴图消息 |
| `ADD_REACTIONS` | 添加反应（含自定义 item） |
| `MANAGE_EXPRESSIONS` | 服管：本服 ban/解 ban 贴图包；服级表情管理入口 |
| `USE_EXTERNAL_EMOJIS` | 首期 **不**用于卡跨服账号包（见 P.10）；可留扩展 |

### 10.2 服务器管理员

| # | 规则 |
|---|------|
| **G.1** | 可对本服 `ban` / 解 ban 指定 `pack_id`。 |
| **G.2** | ban 效果：本服选择器不可见、不可新发该包 item、不可在本服新 Install；**不删除**原包。 |
| **G.3** | 不可直接编辑他人包内容。 |
| **G.4** | 历史消息展示策略：默认仍显示图片；「加入库」入口对已 ban 包隐藏或 403。 |

### 10.3 Web 系统后台

| 动作 | 效果 |
|------|------|
| 全局 ban pack | 全站不可新 Install / 新发；可选强制 library 隐藏 |
| 解全局 ban | 恢复 active（若非软删） |
| 硬删整包 | `purged`；Install 失效；历史按 R.6 |
| 硬删单条 | item `purged`；Copy 副本独立 |
| 调整配额 | 全局默认 / 指定用户 |

所有治理动作写审计日志（操作者、对象、原因、时间）。

## 11. REST API 草图

> 路径前缀以 OpenAPI 正式稿为准；此处定资源与语义。

### 11.1 包与条目（用户）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/users/@me/sticker-packs` | 我创建的包 |
| `POST` | `/users/@me/sticker-packs` | 创建包（kind/scope/name/…） |
| `PATCH` | `/users/@me/sticker-packs/{pack_id}` | 改名、描述、allow_browse_full、封面 |
| `DELETE` | `/users/@me/sticker-packs/{pack_id}` | 作者软删 |
| `POST` | `/users/@me/sticker-packs/{pack_id}/restore` | 180 天内恢复 |
| `GET` | `/sticker-packs/{pack_id}` | 预览元数据；全量 items 受 allow_browse_full 与身份约束 |
| `POST` | `/sticker-packs/{pack_id}/items` | 上传 item（multipart 或先 attachment 再绑定） |
| `PATCH/DELETE` | `/sticker-packs/{pack_id}/items/{item_id}` | 所有者管理条目 |

### 11.2 贴图库

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/users/@me/sticker-library` | 已 Install 列表（仅 active；可选 include_hidden） |
| `PUT` | `/users/@me/sticker-library/{pack_id}` | Install 引用 |
| `DELETE` | `/users/@me/sticker-library/{pack_id}` | 卸装（删 library 行） |
| `POST` | `/users/@me/sticker-packs/{target_pack_id}/items/copy` | body: `{ source_item_id }` 单条复制 |

### 11.3 服管 / 后台

| 方法 | 路径 | 说明 |
|------|------|------|
| `PUT/DELETE` | `/guilds/{guild_id}/sticker-pack-bans/{pack_id}` | 服 ban / 解 ban |
| `GET` | `/guilds/{guild_id}/sticker-pack-bans` | 本服 ban 列表 |
| 后台 | `/admin/sticker-packs/...` | 全局 ban、硬删、配额（鉴权独立） |

### 11.4 消息与反应

- 发送消息：复用 13 号文档 channel messages；扩展 content 节点与 `type=sticker`。  
- 反应：扩展  
  `PUT/DELETE /channels/{id}/messages/{mid}/reactions/{emoji}/@me`  
  中 `{emoji}` 对自定义项使用约定编码（如 `item:item_id` 或 URL-safe mark），OpenAPI 固定。

## 13. 端到端场景

### 13.1 发现与收藏

```text
用户点击消息中的 custom_emote / sticker
  → GET pack 预览
  → allow_browse_full=true 且 active
       → 展示网格 → Install 整包 或 Copy 单条（guild 包无 Copy）
  → allow_browse_full=false 且 account
       → 仅当前项 → 仅 Copy
  → guild 且 browse=false
       → 仅当前项 → 无 Install/Copy
  → soft_deleted*
       → 历史仍显示该项；禁止 Install/Copy
```

### 13.2 发送

```text
选择器只列可用集合
  emote → 插入输入框 → MESSAGE_CREATE（多节点）
  sticker → 直接 sticker 消息
服务端二次校验可用集合 + ban + scope
```

### 13.3 作者软删

```text
DELETE pack
  → pack.soft_deleted
  → 所有 library 行 hidden
  → 安装者库中消失；历史消息仍在
  → 180d 内 restore → library 全员 active
```

## 14. 校验清单（服务端硬约束）

1. `item.kind == pack.kind`  
2. Install 仅当 `allow_browse_full && pack.status==active && !global_ban && scope 合法`  
3. `scope=guild` 拒绝 Copy API  
4. Copy 目标：`owner==me && kind 相同 && item 数 < 配额 && 源包允许 Copy 语义`  
5. 创建 pack：自建数 < 配额  
6. 发送 emote/sticker：∈ 可用集合  
7. sticker 消息：无正文、恰 1 张、kind=sticker  
8. mark/hash：仅服务端生成与校验  
9. 反应：未 purged 可展示与追加；尺寸 UI 侧统一  
10. 软删：library 只 hidden；恢复批量 active；过期不 GC，除非 admin purged

## 16. 定稿决议索引

| 编号 | 决议 |
|------|------|
| 归属 | 包跟账号；可建服独属（scope=guild） |
| 收藏 | 整包 = 引用；单条 = 复制（不跟随） |
| browse=false | 禁 Install；account 可 Copy；guild 无 Copy |
| 小表情标识 | A1 规范 hash + mark；禁手设 shortcode；不在库不能发 |
| 贴图 | 禁止图文混排；一条一贴 |
| 跨服 | account 可；guild 否 |
| 配额 | 收藏不限；自建默认 25 包 × 100 张 |
| 治理 | 服 ban；后台全局 ban / 硬删 |
| 反应 | 小表情+贴图均可；贴图缩放一致 |
| 范围 | 全做（含收藏与拷贝） |
| B3 | 服独属禁止 Copy，仅本服 Install |
| C | 软删；180 天作者可恢复；过期不硬删；Install 软隐藏可恢复；历史保留；软删期禁入库 |
| D | 反应计数与图标保留，仍可追加反应 |
