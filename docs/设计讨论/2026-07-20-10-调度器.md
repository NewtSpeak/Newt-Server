## 1. 目标

| 目标 | 说明 |
|------|------|
| 统一 | **Join 与迁移共用同一打分函数**，不同 **mode** 换权重 profile |
| 池内 | 候选 ⊆ 服节点池；**禁止出池** |
| 可迁 | **5% 容量预留给迁移**，降低热迁失败率 |
| 可配 | 权重、软顶、阈值由系统管配置，带默认值 |
| 安全 | RTT 防作弊截断；合规标签 **硬过滤** |

## 2. 职责与输出（P / X）

| 编号 | 定稿 |
|------|------|
| **P.1** | Join / 迁移 **同一套打分** |
| **P.2** | 仅 Server 调用 |
| **P.3** | 输出 **`primary` + `fallbacks[]`**（有序）；供迁移重试等 **Server 内部** 使用 |
| **X.3** | **fallback 不暴露给客户端**；客户端只接受当前 `VOICE_SERVER_UPDATE` / join 响应中的单一目标 |

### 2.1 API 形态（逻辑）

```text
ScheduleRequest {
  mode: JOIN | MIGRATE_LEAF | MIGRATE_BATCH | MIGRATE_ROOT
  guild_id
  user_id
  logical_room_id?          // 语音频道
  from_node_id?             // 迁移源
  batch_key?                // 批量收敛键，如 from_node+room
  client_region?
  rtt_samples[]?            // { node_id, rtt_ms, measured_at }
  compliance_context?       // 用户/服驻留要求
}

ScheduleResponse {
  primary: node_id
  fallbacks: [node_id…]
  scores: optional debug    // 仅管理/调试
  reservation_id?           // 容量预留
  reservation_ttl?
}
```

### 2.2 上层错误

| 场景 | 行为 |
|------|------|
| Join 无节点 | `503 NO_SFU_CAPACITY` / `NO_NODE_IN_POOL` |
| 迁移无节点 | **不** 回大厅；按 09 **排队重试** |

## 3. 硬过滤（Q / W）

按顺序过滤，**不进入打分**：

| # | 条件 | 动作 |
|---|------|------|
| 1 | 不在 Guild **节点池** | 拒绝 |
| 2 | 非 `ONLINE` / 控制通道不健康 | 拒绝 |
| 3 | **`DRAINING`（Q.1）** | **硬拒** |
| 4 | 源节点（迁移） | 拒绝 |
| 5 | **合规标签不匹配（W.2）** | **硬拒** |
| 6 | 容量不足（含预留规则，见 §3.1） | 拒绝 |

### 3.1 迁移容量预留（Q.2）

| 项 | 定稿 |
|----|------|
| 预留 | 每节点 **约 5%** 容量（或 `max(1, floor(max_users * 0.05))`）**不提供给 Join** |
| Join | 仅当 `used + 1 ≤ max_users - reserve` 才可通过硬过滤 |
| 迁移 | 可使用含预留在内的容量：`used + 1 ≤ max_users` |
| 可配 | 比例系统管可调；默认 **5%** |

### 3.2 标签（W.1 / W.3）

示例标签：`region`、`country`、`compliance=in_country`、`network=private|public`。

- **池** = 候选宇宙  
- **标签硬滤** = 池内再截断  
- 服策略可声明 `must_match`（如强制某 region）

## 4. 软打分（R）

### 4.1 模型（R.1）

各因子归一化到 **[0, 1]**（越高越好），加权和：

\[
score = w_r S_{rtt} + w_g S_{region} + w_c S_{capacity} + w_s S_{sticky} + w_a S_{tree}
\]

（文档中 \(S_{anchor}\) 与「已在树/根」合并为 \(S_{tree}\)。）

| 因子 | 计算要点 |
|------|----------|
| \(S_{rtt}\) | RTT 越低越高；映射可用线性或分段；**无样本 → 0.5（R.4）** |
| \(S_{region}\) | 客户端 region 与节点标签一致 → 1；同大区部分分；否则 0 |
| \(S_{capacity}\) | 剩余用户余量、CPU、出口带宽综合；越空越高 |
| \(S_{sticky}\) | 该节点上 **同 logical_room 用户数** 越多越高（有上限饱和） |
| \(S_{tree}\) | 已是本房 **anchor** 或 **已在级联树上** → 加分（少建边） |

### 4.2 默认权重（R.3）与可配（R.2）

| Profile | \(w_r\) RTT | \(w_g\) region | \(w_c\) capacity | \(w_s\) sticky | \(w_a\) tree |
|---------|-------------|----------------|------------------|----------------|--------------|
| **JOIN** | 0.35 | 0.20 | 0.25 | **0.10** | 0.10 |
| **MIGRATE_LEAF** | 0.25 | 0.15 | 0.25 | **0.25** | 0.10 |
| **MIGRATE_BATCH** | 0.15 | 0.15 | 0.25 | **0.35** | 0.10 |
| **MIGRATE_ROOT** | 先选 anchor 规则（08）；用户再按 LEAF/BATCH | — | — | — | — |

- 权重 **系统管可配**，须归一或自动 renormalize。  
- 调参后写审计，避免静默变更。

### 4.3 同分与微扰（V.2 / V.4）

| 项 | 定稿 |
|----|------|
| 同分 | `hash(user_id, node_id)` **稳定打散** |
| Join | 允许 **1–2%** 随机微扰，防羊群 |
| 迁移 | **关闭** 随机微扰，结果更可复现 |

## 5. 调度 Mode（U）

| Mode | 场景 | 策略要点 |
|------|------|----------|
| `JOIN` | 正常 `POST /voice/join` | 偏 RTT/region；弱 sticky；**不强制** 与同房同节点（T.1） |
| `MIGRATE_LEAF` | 叶迁、单用户过载迁 | 提高 sticky；排除 from；树加分 |
| `MIGRATE_BATCH` | 死亡 / Drain / 批量过载 | **先选 batch_target**（U.2），再尽量把同批用户塞入；容量不够再 fallback |
| `MIGRATE_ROOT` | Anchor 死亡 | 先按 08 **人最多等** 选新根并构图；再对用户跑迁移调度 |

### 5.1 BATCH 先定目标（U.2）

```text
1. 对 batch 代表（或虚拟请求）跑打分，取 primary 为 batch_target
2. 同批用户：优先 schedule 到 batch_target（容量允许）
3. 溢出用户：用 fallbacks 或重新打分（仍偏 sticky）
```

## 6. 同房与级联相关（T）

| 编号 | 定稿 |
|------|------|
| **T.1** | Join **不强制** 同节点（保证按地域多节点） |
| **T.2** | 故障批量 **强收敛**（见 BATCH） |
| **T.3** | **已在树 / anchor 加分**（\(S_{tree}\)） |
| **T.4** | **单节点同房人数软顶可配**：接近/超过则 **降分**（非硬拒）；频道硬顶 200 仍在业务层 |

软顶默认值实现期可先给建议（如 80），**产品/系统管可改**；未配置则仅不启用降分或使用内置默认。

## 7. 客户端 RTT 探测（S）

| 编号 | 定稿 |
|------|------|
| **S.1** | 对 **服候选池节点**：**后台探测 + 进房前补测** |
| **S.2** | 探测 endpoint 与媒体口 **分离更佳**（实现细节可定 UDP/HTTP） |
| **S.3** | Server **截断/限幅** 异常 RTT（防作弊刷分）；仅作软因子 |
| **S.4** | 样本 **TTL = 60s**；过期视为无样本 → \(S_{rtt}=0.5\) |
| **S.5** | 探测失败 = 无样本，不硬拒节点 |

```text
ClientReportRtt {
  samples: [{ node_id, rtt_ms, measured_at }]
}
// Server: clamp rtt_ms to [rtt_min, rtt_max]; discard too old; discard impossible jumps
```

## 8. 容量占位（V.1）

| 项 | 定稿 |
|----|------|
| 时机 | Join 成功选点后 / 迁移 **PREPARE** 时 **预留 slot** |
| 内容 | `reservation_id` + TTL（建议数秒～与 CONNECT 超时对齐） |
| 成功 | 会话建立后转为正式占用，释放 reservation 记账 |
| 失败/超时 | 自动释放，防超卖与泄漏 |

Join 占用计入「非预留区」；迁移占用可吃 5% 预留区。

## 9. 端到端流程摘要

### 9.1 Join

```text
硬过滤 → mode=JOIN 打分 → primary+fallbacks
→ 预留 slot(primary)
→ EnsureRoom + 级联边（08）
→ 边就绪 → token → 客户端
// 若 primary 失败（边/ICE），Server 可用 fallbacks 换点，客户端仍只收新的单一目标
```

### 9.2 叶迁移

```text
mode=MIGRATE_LEAF → 排除 from → 打分 → 预留
→ 边就绪 → VOICE_MIGRATING / VOICE_SERVER_UPDATE → 09 状态机
```

### 9.3 批量（死亡/Drain）

```text
mode=MIGRATE_BATCH → 选 batch_target → 批量占位
→ 构图/挂边 → 并行/限流跑各会话 09 状态机
```
