## 1. 架构

```
信号源（message/reactions/gateway IDENTIFY/语音采样）
  → tracker 内存聚合（30s flush 批量 UPSERT 增量）→ user_activity_days
  → settler 每小时结算已过界业务日：计分 → cosmetics.GrantPointsTx 发积分
  → user_activity_stats（总分/等级）→ ACTIVITY_LEVEL_UP / publicProfile.activity_level
```

- 业务日按 `ActivitySetting.DayOffsetMinutes` 切分，默认 480（北京时间 UTC+8）。
- 信号走直接函数调用（`activity.TrackMessage/TrackReaction/TrackLogin`），不走 eventbus（缓冲满会丢事件）。
- 语音用采样式累计（每分钟扫 `voice_states connected=true`），天然抗客户端崩溃；排除 bot 与隐身管理员。
- 依赖方向：`message→activity`、`activity→cosmetics`；`gateway.OnIdentify` 与 `activity.StealthCheck` 在装配层桥接，避免 `voice→message→activity→gateway/voice` 成环。

## 2. 计分与发放

- 每日分 = Σ min(计数, 日上限) × 权重；原始计数落库不截断（配置可回溯），上限在结算时应用。
- 默认：消息 10×60、语音 2 分/分钟×240、反应 1×30、登录 20×1（日满分 1130）；消息 30s 限流内多条只计 1。
- 积分 = floor(每日分 × points_rate × (1 + min(等级×每级加成%, 封顶%)/100))，**加成按结算前等级快照**。
- 等级门槛可配置 JSON 数组（严格递增），空/非法回退默认曲线 `50L²+50L`（Lv1=100…Lv50=127500）。
- 幂等：`(user_id, day)` 主键 + 结算 `granted=false` 行级 CAS + ledger `reason=activity_daily refType=activity refID=业务日`。

## 3. API 摘要

### 用户端 `/gapi/v1`
- `GET /users/@me/activity?days=N` — 今日各维度/预估分 + caps/weights + 总分/等级/下一级进度 + 历史
- `GET /users/:id`（publicProfile）附 `activity_level`

### 管理端 `/api/v1/admin/activity`（system_admin）
- `GET|PUT /config`、`GET /stats?day=`、`GET /users/:id?days=`、`POST /settle`

### Gateway（定向本人）
- `ACTIVITY_UPDATE`（flush 后今日快照）、`ACTIVITY_LEVEL_UP`；`COSMETIC_POINTS_UPDATE` 载荷扩展 `delta/reason`
