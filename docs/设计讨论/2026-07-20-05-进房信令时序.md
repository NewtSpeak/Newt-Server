## 1. 通道分工

| 通道 | 端点 | 载荷 |
|------|------|------|
| **客户端 ↔ Newt-Server** | HTTPS REST + **Gateway WebSocket** | 登录、业务 API、服务器/频道事件、**语音会话编排** |
| **客户端 ↔ Newt-SFU** | WebRTC（UDP/ICE）+ 可选 SFU 数据通道 | **仅媒体**；入会用 Server 签发的 Media Token |
| **Newt-Server ↔ Newt-SFU** | mTLS 控制通道 | 建房、踢人、改 caps、心跳；**无 RTP** |

客户端 **不得** 要求 SFU 信任「我有管理员权限」类自述。

---

## 2. 标识与状态

### 2.1 ID

| ID | 含义 |
|----|------|
| `user_id` | 平台用户 |
| `guild_id` | 服务器 |
| `channel_id` | 语音子频道 |
| `node_id` | SFU 节点 |
| `room_id` | SFU 上房间；首期可 `room_id = channel_id` 或映射表 |
| `voice_session_id` | Server 侧一次语音会话（用户在频道内） |
| `jti` | Media Token 唯一 ID |

### 2.2 Server 侧语音状态（逻辑）

```text
VoiceState {
  user_id, guild_id, channel_id?
  node_id?, room_id?, voice_session_id?
  self_mute, self_deaf
  server_mute, server_deaf
  connected: bool          // 是否已完成 SFU 入会（可由 SFU 事件确认）
}
```

同用户在同一 `guild` **同时只能处于一个语音频道**（对标 Discord）；切换 = 先离后进或原子切换。

## 3. 正常进房（Happy Path）

### 3.1 时序图

```text
Client                    Newt-Server                      Newt-SFU
  │                           │                              │
  │  Gateway: 已认证连接        │                              │
  │                           │                              │
  │ 1. VoiceJoinIntent        │                              │
  │    POST /voice/join       │                              │
  │    { guild_id, channel_id, │                              │
  │      self_mute, self_deaf }│                              │
  │                           │                              │
  │                           │ 2. RBAC: VIEW+CONNECT        │
  │                           │    (+ 成员 timeout/封禁检查)   │
  │                           │ 3. 若已在其他语音频道 → 先内部 Leave
  │                           │ 4. 解析/创建 room 绑定节点      │
  │                           │    （粘性：频道已有人则同节点） │
  │                           │ 5. 若 room 未在节点：          │
  │                           │    CreateRoom(room_id, …) ──►│
  │                           │    ◄── OK ──────────────────│
  │                           │ 6. 计算 caps（SPEAK/mute…）   │
  │                           │ 7. 签发 Media Token          │
  │                           │ 8. 写 VoiceState（pending）   │
  │                           │ 9. 广播 VOICE_STATE_UPDATE     │
  │ ◄── 200 {                 │    （guild 内相关成员）        │
  │       token, node_id,     │                              │
  │       room_id,            │                              │
  │       ice_servers,        │                              │
  │       sfu_endpoint_hint,  │                              │
  │       caps, session_id }  │                              │
  │                           │                              │
  │ 10. WebRTC:               │                              │
  │     DTLS/ICE + 带 token   │                              │
  │     加入 room ──────────────────────────────►│
  │                           │                              │ 11. 验 token:
  │                           │                              │     sig/exp/nid/rid/caps
  │                           │                              │ 12. 建立 PC，按 caps
  │                           │                              │     允许 publish/subscribe
  │ ◄──── media 连通 ─────────────────────────────│
  │                           │                              │
  │                           │ ◄── ParticipantJoined ──────│
  │                           │ 13. VoiceState.connected=true│
  │                           │ 14. 可选再广播 VOICE_STATE    │
  │                           │                              │
  │ 15. 发布/订阅音频 ◄──────────────────────────►│
```

### 3.2 REST：`POST /voice/join` 失败码（逻辑）

| 条件 | 结果 |
|------|------|
| 未登录 | 401 |
| 非成员 | 403 |
| 无 `VIEW_CHANNEL` / `CONNECT` | 403 |
| 频道不存在/非语音 | 404 |
| 无可用 SFU | 503 `NO_SFU_CAPACITY` |
| 频道满员 | 403 `CHANNEL_FULL` |

### 3.3 Media Token 校验失败（SFU）

关闭连接并可选原因码：`TOKEN_EXPIRED` / `TOKEN_INVALID` / `WRONG_NODE` / `ROOM_MISMATCH` / `CAP_DENIED`。  
客户端应回 Server **刷新 token** 或重新 `join`，避免死循环（限次）。

## 4. Token 刷新（续会）

| 项 | 约定 |
|----|------|
| TTL | 建议 **2–5 分钟** |
| 刷新 | 过期前 Client `POST /voice/refresh-token`（仍在原 channel） |
| Server | 重算 caps → 新 token（新 `jti`/`exp`） |
| SFU | 支持 **UpdateToken** 或短中断重协商；推荐在位更新避免断音频 |
| 失败 | caps 已无 `join` → 走踢出流程 |

## 5. 主动离房

```text
Client → Server: POST /voice/leave  或  Gateway VoiceLeave
Server:
  - 清 VoiceState.channel
  - 控制通道 DisconnectUser(room, user) → SFU
  - 广播 VOICE_STATE_UPDATE (channel_id=null)
Client: 关闭 PeerConnection
SFU → Server: ParticipantLeft（幂等）
```

客户端直接杀进程：靠 SFU ICE 超时 → `ParticipantLeft` → Server 校正状态（**最终一致**）。

---

## 6. 切换语音频道

```text
Server 在同一 join 请求内:
  1) 对旧 channel 执行 leave（Disconnect + 广播）
  2) 对新 channel 执行 join（可能换 node → 客户端必须重建 PC）
响应中带 move: true, previous_channel_id, 若 node 变化则 force_reconnect: true
```

跨节点切换：**必须** 重建 WebRTC，无法无缝。

## 7. 权限变更 → 实时媒体生效

### 7.1 会触发重算的事件

- 角色权限 / 成员角色 / 频道 overwrite 变更  
- 服务器 mute / deafen / timeout  
- 管理员踢出语音、移动成员  
- 失去 `CONNECT` / `VIEW_CHANNEL` / `SPEAK`

### 7.2 通用流程

```text
权限源变更
    │
    ▼
Server: 找出受影响且 connected 的 VoiceState 用户列表
    │
    ▼
对每一用户 recompute caps / 是否仍可留在频道
    │
    ├─ 仍可 join，caps 变化
    │     Server → SFU: UpdateParticipantCaps(user, caps)
    │     Server → Client (Gateway): VOICE_CAPS_UPDATE / VOICE_STATE_UPDATE
    │     SFU: 立刻 stop publish 或限制 subscribe
    │
    └─ 不可再 join（无 CONNECT/VIEW 等）
          Server → SFU: DisconnectUser(reason=PERMISSION)
          Server: 清 VoiceState
          广播 VOICE_STATE_UPDATE
          Client: 收到后关 PC + UI 提示
```

### 7.3 映射表（操作 → 媒体）

| 业务操作 | Server | SFU | Client |
|----------|--------|-----|--------|
| 去掉 `SPEAK` | 重算 caps 去掉 `publish_audio` | 禁止/停止上行，可继续下行 | UI 显示禁言（权限） |
| 服务器 Mute | `server_mute=true`，caps 去 publish | 同上 | 显示服务器静音 |
| 服务器 Deafen | `server_deaf=true` | 停止下行（及通常也停上行） | 显示服务器耳聋 |
| 去掉 `CONNECT`/`VIEW` | 断会话 | DisconnectUser | 被移出频道 |
| Timeout 生效 | mask 发送/说话 | 更新 caps 或断开策略见 RBAC 文档 | 提示禁言 |
| 踢出服务器 | leave 所有语音 + 成员删除 | Disconnect | 退出 UI |
| `MOVE_MEMBERS` 到频道 B | 原子 leave A + join B 编排 | 可能换 room | 按 join 响应重连 |

### 7.4 生效时延目标

| 指标 | 目标 |
|------|------|
| 权限撤销到 SFU 停推流 | **P99 < 1s**（同城控制通道） |
| Gateway 通知客户端 | 与上接近 |
| 无 SFU 事件时状态校正 | ICE 超时内（如 15–45s） |

## 8. 踢出与强制断开

### 8.1 管理员踢出语音（仍留在服务器）

```text
Admin → Server: POST /guilds/{gid}/voice/disconnect { user_id }
Server: 检查 MUTE/MOVE 类权限与角色层级
Server → SFU: DisconnectUser(reason=ADMIN)
Server: VoiceState 清空 channel
广播 VOICE_STATE_UPDATE
目标 Client: Gateway 事件 reason=ADMIN_DISCONNECT
```

### 8.2 无权限残留

即使 Client 恶意不关 PC：SFU 已 Disconnect，无媒体；Token 刷新也会失败。

---

## 9. 自我状态（Mute / Deaf）

```text
Client → Server: PATCH VoiceState { self_mute, self_deaf }
Server: 更新并广播 VOICE_STATE_UPDATE
Client: 本地停采/停放（主）
SFU: 可选根据协议停发 track（双保险）
```

**注意：** `self_mute` 与 `server_mute` 独立；恢复说话需 **两者都允许** 且具备 `SPEAK`。

## 10. SFU / 控制通道异常

| 故障 | 行为 |
|------|------|
| SFU 进程崩溃 | 房间全灭；Server 心跳发现节点 OFFLINE；批量清 VoiceState 或标记 reconnect；广播用户需重进 |
| 控制通道断开，媒体仍在 | 短时容忍（如 30s）；期间 **无法** 踢人/改 caps；超时后 Server 视节点不可用并触发排空策略 |
| Server 重启 | **应** 从 SFU 反查恢复 VoiceState + 必要热迁移；目标仍是 **自动恢复**，非用户手动重进 |
| Token 过期未刷新 | SFU 断开；Client 自动 refresh；迁移场景由 Server 推新 `VOICE_SERVER_UPDATE` |
| **节点故障** | Server 选池内 **最近 + 占用最低** 节点 → **热迁移**（级联/快速重绑）；**不接受**「短中断手动重连」作为合格方案 |

热迁移完整状态机 → 专项文档（06 衍生 #1）。

## 11. Gateway 事件（定稿方向）

| 事件 | 方向 | 用途 |
|------|------|------|
| `VOICE_STATE_UPDATE` | S→C | 某人语音状态（进/出/ mute/台上台下） |
| `VOICE_SERVER_UPDATE` | S→C | **辅助路径**：endpoint/token 推送（进房、重连、**热迁移**） |
| `VOICE_CAPS_UPDATE` | S→C | 本地 caps 变化（禁说、下麦等） |
| `VOICE_CHANNEL_STATUS` | S→C | 频道人数/舞台状态等 |
| `VOICE_PACK_PLAY`（或等价） | S→C | **入场语音包**：进服/配置场景播放指定音频 |

**主路径**：REST `POST /voice/join` 拿 token + 错误码。  
**辅助路径**：`VOICE_SERVER_UPDATE` 统一客户端状态机（含迁移）。

## 12. 文本频道对照（非媒体）

## 13. 安全检查清单（时序相关）

1. Join 只在 Server 鉴权后发 token。  
2. Token 绑定 `nid`+`rid`+`uid`+`exp`+`caps`。  
3. 权限下调必须 **Server→SFU 控制指令**，不能只靠 Client。  
4. 管理员操作校验角色层级。  
5. 所有 Disconnect/UpdateCaps **幂等**。  
6. 审计：踢人、强制 mute、权限导致断开可写 audit log。

| # | 结论 |

| 1 | 进房：Client→Server 鉴权调度签发 token → Client↔SFU WebRTC；媒体不经 Server |
