## 1. 目标

| 目标 | 说明 |
|------|------|
| 自动恢复 | 节点死亡、分区、Drain、过载（可配自动）时，会话 **自动** 迁到池内合适节点 |
| 可控 | 系统管全权手动；服管仅本服会话；过载自动默认关 |
| 可观测 | 全链路 `migration_id`、审计、指标 |
| 与级联一致 | 叶迁尽量不换根；根死走 08 切根顺序 |

## 2. 迁移对象（H）

| 编号 | 定稿 |
|------|------|
| **H.1** | 单位 = **用户语音会话**（`user_id + guild_id` 下当前逻辑语音房中的媒体会话） |
| **H.2** | 节点死亡 → 该节点上 **全部** 相关会话迁出 |
| **H.3** | **音画同迁**（音频 + 屏幕等轨同一会话、同一目标节点） |

级联 peer **不是** 迁移对象（非用户会话）。

```text
VoiceSession {
  user_id, guild_id, channel_id / logical_room_id
  node_id, voice_session_id
  migration_state, migration_id?
  caps, stage_role, …
}
```

## 3. 触发（I）

### 3.1 总表

| 触发 | 自动 | 手动 | 说明 |
|------|------|------|------|
| **节点死亡** | ✓ | ✓ | 见 I.1 |
| **网络分区** | ✓ | ✓ | Server 连不上 / 级联退化，见下 |
| **Drain** | ✓ | ✓ | 排空；时限 I.6 |
| **过载** | **可配，默认关** | ✓ | 批量子 I.5 |

优先级（**K.4**）：**死亡 > 分区 > Drain > 过载**  
进行中的低优先级迁移可被高优先级 **抢占/合并**。

### 3.2 死亡判定（I.1）

| 项 | 定稿 |
|----|------|
| 条件 | 控制通道心跳 **连续 3 次失败** |
| 间隔 | 建议 5–10s 一次心跳（实现可配，语义保持「3 次失败」） |
| 效果 | 节点 → 非调度；其上会话进入迁移 |

### 3.3 分区判定

| 项 | 定稿 |
|----|------|
| Server 视角 | 与死亡类似：控制通道不可用即不可编排该节点 |
| 补充信号 | 级联 `EdgeDown` 且节点曾上报异常，可标 `DEGRADED` 并触发迁出该节点用户 |
| 权威 | **以 Newt-Server 判定为准**，避免分区两侧双活脑裂 |

### 3.4 过载（I.3–I.5）

| 项 | 定稿 |
|----|------|
| 指标 | CPU、出口带宽、并发用户等 **超阈值持续 T 秒**（T/阈值可配） |
| 自动开关 | **默认关**；系统管（及策略配置）可开 |
| 每轮批量 | **≤ 该节点上会话的 15%**，且 **≤ 50 人**（取更严） |
| 冷却 | 每轮后冷却再评估，防止雪崩打满邻居 |

### 3.5 Drain（I.6）

| 项 | 定稿 |
|----|------|
| 进入 DRAINING | 不再调度新会话；开始迁出已有会话 |
| 时限 | **60s** 内尽量迁完；超时 **硬迁** 剩余会话 |
| 与发布 | 升级/下线节点标准路径 |

### 3.6 手动权限（I.7）

| 角色 | 能力 |
|------|------|
| **系统管理员** | 任意节点 Drain、任意会话迁移、开关过载自动、查看详细原因 |
| **服务器管理员** | 仅 **本服** 节点池语义下：迁移/排空 **本服用户会话**；**不能** 直接 Drain 平台节点进程本身 |

## 4. 目标节点选择（J）

### 4.1 硬过滤（J.1）

候选必须同时满足：

1. ∈ 该 Guild **节点池**  
2. `ONLINE` 且控制通道健康  
3. **非** `DRAINING`  
4. **非** 源节点  
5. 容量允许（预留迁入名额）

**禁止出池**（与 07 一致）。

### 4.2 排序（J.2 / J.3）

加权综合分（权重可配），建议因子：

| 因子 | 含义 |
|------|------|
| 近 | 客户端历史 RTT（若有）> region 匹配 > 节点间 RTT |
| 低负载 | CPU/带宽/并发余量 |
| **同房粘性** | 目标上 **已有同 logical_room 用户** 加分（减少建边、利于收敛） |

### 4.3 池满（J.4）

- 无合格目标 → **排队重试**（指数退避 + 上限）  
- UI 可保持「切换中」；**禁止** 引导回大厅手动进房  
- 可伴随短静音/只保留信令在线

### 4.4 同房收敛（J.5）

- 同一源节点、同一 logical_room 批量迁出时：**尽量同一目标**  
- 目标容量不足再拆到次优节点

## 5. 会话状态机（K）

### 5.1 五段状态（K.1）

```text
STABLE
  │ 触发
  ▼
MIGRATING_PREPARE     // 选目标、占位、构图/边、发 migration_id
  │
  ▼
MIGRATING_CONNECT     // VOICE_SERVER_UPDATE；客户端建新 PC；双 PC
  │
  ▼
MIGRATING_CUTOVER     // 发送从旧切到新；接收已在新
  │
  ▼
MIGRATING_CLEANUP     // 拆旧 PC；源 SFU 删参与者；清边若空
  │
  ▼
STABLE

任一阶段超时/失败 → MIGRATING_FAILED → 重试或保持自动恢复
```

### 5.2 建议段超时（可配，K.2 量级）

| 阶段 | 建议超时 |
|------|----------|
| PREPARE | ~2s |
| CONNECT | ~5–8s |
| CUTOVER | ~2s |
| CLEANUP | ~3s |

### 5.3 重试（K.3）

| 项 | 定稿 |
|----|------|
| 次数 | 最多 **3 次**，每次可 **换目标节点** |
| 仍失败 | 后台继续按策略排队重试；UI「切换中」；**禁止**要求用户回大厅 |

### 5.4 并发与优先级（K.4 / K.5）

| 项 | 定稿 |
|----|------|
| 锁 | 同一 `user_id + guild_id` 同时仅一个 `migration_id` |
| 抢占 | 死亡 > 分区 > Drain > 过载 |

```text
MigrationJob {
  migration_id
  reason: DEATH | PARTITION | DRAIN | OVERLOAD | MANUAL
  priority
  user_id, guild_id, logical_room_id
  from_node_id, to_node_id?
  epoch?              // 若伴随构图
  state
  attempt
  created_at, updated_at
}
```

## 6. 与级联 / epoch 协作（L）

| 编号 | 定稿 |
|------|------|
| **L.1** | **叶节点** 迁用户：**尽量不换根**；Ensure 目标 local room + 保证到 anchor 路径边 + 迁用户 |
| **L.2** | **源即 Anchor 死亡**：严格走 [08 §7.1](./2026-07-20-08-级联协议与Anchor.md)：冻 epoch → 新根 → 挂边 → 迁用户 |
| **L.3** | 迁入节点边未就绪：**EdgeUp 前不完成满血开音**（短静音），与 08 C.4/E.3 一致 |
| **L.4** | 每次迁移唯一 `migration_id`；触图则绑定新 `epoch`，指令幂等 |

### 6.1 叶迁时序（根健康）

```text
1. PREPARE: 选 to_node；占容量；EnsureLogicalRoom(to)
2. 若 to 无到 anchor 路径: SetCascadeEdges → EdgeUp
3. CONNECT: 签发新 Media Token(nid=to)；VOICE_MIGRATING + VOICE_SERVER_UPDATE
4. 客户端双 PC：新连接建立；接收可先走新
5. CUTOVER: 发送切到新 PC
6. CLEANUP: 旧 PC 关；from 节点 RemoveParticipant；更新 VoiceState.node_id
7. STABLE
```

### 6.2 根死时序

见 08 §7.1，迁移子系统在步骤「迁用户」阶段对每个会话跑 §5 状态机（可并行批量，注意目标容量与 J.5 收敛）。

## 7. 客户端协议（M）

### 7.1 事件

| 事件 | 方向 | 作用 |
|------|------|------|
| `VOICE_MIGRATING` | S→C | 进入迁移；可带模糊原因、`migration_id` |
| `VOICE_SERVER_UPDATE` | S→C | 新 node 接入信息 + token |
| `VOICE_MIGRATED`（建议） | S→C | 成功结束，可清 UI |
| `VOICE_STATE_UPDATE` | S→C | node/channel 等状态对齐 |

### 7.2 双 PC 与发送切换（M.3）

| 阶段 | 发送 | 接收 |
|------|------|------|
| CONNECT | **仍走旧 PC** | 可开始走新 PC（或双收选优） |
| **CUTOVER 瞬间** | **切到新 PC** | 新 PC |
| CLEANUP | 新 | 新；拆旧 |

禁止长期双发（回声/抢麦）。  
允许 CUTOVER 附近 **极短静音** 作缓冲。

### 7.3 客户端无响应（M.4）

- 超时后 Server 仍以目标节点为权威占位，源侧踢旧。  
- 客户端 Gateway 重连后拉取 VoiceState / 补 `VOICE_SERVER_UPDATE` 跟随。  
- **不** 掉进「必须手动进房」流程。

## 8. 过载公平性（N）

| 编号 | 定稿 |
|------|------|
| **N.1** | 优先迁移 **听众 / 非台上**；**尽量不迁台上发言者** |
| **N.2** | 同优先级下可偏好 **进房时间短、当前未在说话** 的会话 |

死亡/分区/Drain：**全员必须迁**，不受「听众先」限制（台上也迁，但可优先保障台上会话的目标质量/同目标收敛）。

## 9. 审计与用户文案（O）

### 9.1 审计（O.1）

每次迁移记录至少：

- `migration_id`, reason, priority  
- from/to node, user, guild, channel  
- 触发者：`auto` / `system_admin` / `guild_admin`  
- 各阶段时间戳、attempt、成功/失败码  

### 9.2 用户可见原因（O.2）

| 模式 | 定稿 |
|------|------|
| **默认** | **模糊**文案（如「线路优化中」「节点维护切换中」） |
| **详细** | **系统管理员可暂时开启** 展示技术原因（节点 ID、reason 码等） |
| 管理端 | 始终可看完整审计字段 |

## 10. 失败与边界

| 场景 | 行为 |
|------|------|
| 3 次重试失败 | 排队再试；指标告警；用户仍见切换中/短静音 |
| 迁移中用户主动 leave | 取消 job，CLEANUP 双侧 |
| 迁移中切语音频道 | 取消迁，走正常 leave+join |
| 目标在 CONNECT 期死亡 | 失败重试，换目标 |
| 过载自动关闭时仅手动 | 只告警不自动迁（除非死亡等） |

## 12. 结论汇总

| # | 结论 |
|---|------|
| 1 | 用户会话为粒度；音画同迁 |
| 2 | 死亡=3 次心跳失败；过载自动默认关；批≤15% 且≤50；Drain 60s 硬迁 |
| 3 | 手动：系统管全权，服管仅本服会话 |
| 4 | 选点：池内 + 近/低载/**同房粘性**；池满排队；批量尽量同目标 |
| 5 | 五段状态机；重试 3 次换目标；优先级 死亡>分区>Drain>过载 |
| 6 | 叶迁不换根；根死走 08 切根 |
| 7 | 旧发至 CUTOVER 再切新；双 PC |
| 8 | 过载优先迁听众；用户文案默认模糊，系统管可开详细 |
