# 专项 1：SFU 级联 + 热迁移

## 1.1 体验 SLA

| 项 | 定稿 |
|----|------|
| 硬性禁止 | **不允许**「掉线回大厅 / 手动再点进房」作为故障恢复路径 |
| 允许 | 切换 SFU 时 **短暂静音**（客户端换节点） |
| 量化目标 | 尽量高；实现与压测阶段给出 P99 静音时长指标（目标方向：**秒级内**自动恢复媒体，无需用户操作） |

## 1.2 迁移策略

| 项 | 定稿 |
|----|------|
| 策略 | **混合**：客户端快速换节点（可短暂静音）+ 服务端 **池内级联桥接** 过渡/跨节点同房 |

## 1.3 级联拓扑

| 项 | 定稿 |
|----|------|
| 拓扑 | **树形或有根星型** |
| Anchor | **每个「服务器」(Guild) 或每个语音逻辑房间** 在池内选举 **anchor 节点**（细则实现期定：偏「每语音频道一个逻辑根」） |
| 禁止 | **禁止随意全连接** 网格级联 |

## 1.4 常态多节点（重大）

| 项 | 定稿 |
|----|------|
| 进房 | **同一语音频道从一开始就多节点接入** |
| 选点 | 按用户 **地域 / RTT**（见专项 2）进入 **不同 SFU 节点** |
| 媒体 | **节点之间转发音频流（池内级联）**，组成同一逻辑语音房 |
| 故障 | 故障节点上的用户 **自动** 将音频会话接到 **最近的存活节点**（池内、低负载优先，见 2.x） |

> 废止「默认单节点粘性、仅故障才迁」作为主路径。单节点仅可能作为「池内仅一节点可用」的退化情形。

## 1.5 迁移触发

| 触发 | 自动 | 手动 |
|------|------|------|
| 节点死亡 | ✓ | ✓（运维可干预） |
| 过载 | **可配置是否自动** | ✓ |
| 运维 Drain | ✓（排空迁移） | ✓ |
| 网络分区 | ✓（检测到分区/不可用后） | ✓ |

编排权威：**Newt-Server**；执行：Newt-SFU + 客户端 `VOICE_SERVER_UPDATE` / 换 token。

### 专项 1 注意（实现约束）

1. 级联边只存在于 **服节点池内**（与 2.4 一致）。  
2. 迁移幂等：`migration_id`，防控制通道重放。  
3. 台上/麦序/Restriction 状态以 **Server** 为准，迁移后回放 caps。  
4. Anchor 故障时需 **重选根 + 重构树**，避免脑裂双根。  
5. 跨境级联带宽成本高，监控 **节点间中继 bps** 为独立指标。

# 专项 2：服级节点池 + 跨境调度

## 2.1 配置权限

| 角色 | 能力 |
|------|------|
| **系统管理员** | 定义平台节点、**标签**（region、合规、容量档等）、授权「哪些节点可被哪些服选」 |
| **服务器管理员** | 仅能从 **被授权候选** 中勾选 **本服节点池**；**不能** 把流量指到未审核机器 |

## 2.2 空池 / 未配置

| 项 | 定稿 |
|----|------|
| 默认 | **回落平台默认池** |
| 开关 | **可关闭回落**（关闭后无池则无法语音或明确失败） |

## 2.3 「近」与调度输入

综合三类信号（**全部要做**）：

1. **客户端 RTT 探测**（对候选节点）  
2. **region 标签**  
3. **节点上报** RTT/容量/负载  

调度目标：近 + 低占用（加权；权重实现期可配）。

## 2.4 池边界

| 项 | 定稿 |
|----|------|
| 用户调度 | **禁止出池** |
| 级联 | **只在池内**，禁止池外级联边 |

## 2.5 多 region

| 项 | 定稿 |
|----|------|
| 同服池 | **允许** 多 region 节点同池 |
| 目的 | 跨境用户就近入点，体验更好 |
| 配合 | 同语音频多节点 + 池内级联（专项 1.4） |

### 专项 2 注意

1. 合规标签（数据不出境等）必须能 **限制候选集**，优先于 RTT。  
2. 池变更删节点 → Drain/热迁，勿只禁新进。  
3. 系统管改池 → **审计**。  
4. 客户端 RTT 探测需防作弊（仅作调度参考，Server 可校验合理性）。

# 专项 3：舞台 / 听讲 / 麦序 / 协管

## 3.1 模式与 &gt;50 策略

| 项 | 定稿 |
|----|------|
| 频道模式 | 可配置：**自由讨论** / **舞台** |
| 人数 &gt;50 | **强制舞台**；应 **提示升级/切换模式** |
| 若未进入合规舞台形态 | 对 **第 51 人及之后进房者** 按进房顺序 **自动禁说**（可听） |
| 有人离开 | 按 **先后顺序** 对曾被自动禁说的用户 **逐个解除** 自动禁说（名额回补） |

> 语义：避免静默带宽爆炸；不是简单踢出，而是 **超额自动禁说 + 有序释放**。

## 3.2 台上人数

| 项 | 定稿 |
|----|------|
| **软限制** | **20**（默认推荐/提示） |
| **硬顶** | **最多不超过 50**（不可配置超过 50） |
| 可配 | 频道/服可在 **1–50** 内配置目标上限，默认贴近软限 20 |

> **修订 06**：原「最多 20」改为软 20 / 硬 50。

## 3.3 听众听感

| 项 | 定稿 |
|----|------|
| 默认下行 | 听众 **能听全部台上** |
| 客户端 | 可 **自由静音某路上台用户**，实现只听主咖 / 听多个 / 全听切换 |
| 服务端 | 不强制「仅主咖一路」；主咖体验以 **客户端选听** 为主（带宽仍按台上人数订） |

## 3.4 上麦

| 项 | 定稿 |
|----|------|
| 机制 | **申请队列** + 管理/协管 **抱上 / 抱下** |
| 可配 | **关闭申请，仅抱麦** |
| 大房 | **禁止自由上麦**（无申请/无抱不可 publish） |

## 3.5 协管

| 项 | 定稿 |
|----|------|
| 模型 | **频道任命协管列表** + **权限节点** |
| 授予 | 可被 **服角色模板** 授予协管类节点 |

## 3.6 小房舞台

| 项 | 定稿 |
|----|------|
| ≤50 | **允许** 开舞台（讲座/讲课） |

### 专项 3 注意

1. 台上最多 50 路上行时，听众全订台上 → 单听众下行仍高，需监控；客户端静音 **不减少** SFU 已转发流量，除非做 **选择性订阅信令**（建议二期：客户端取消订阅某 speaker 通知 SFU 停该路）。  
2. 「自动禁说」与 Restriction/麦序状态机勿冲突：自动禁说应标来源 `CAPACITY_QUEUE`。  
3. 抱麦改 caps 必须 **Server → SFU 控制通道** 即时生效。

# 专项 4：多维 Restriction

## 4.1 维度

**四维可组合**：文字 **看 / 说**、语音 **听 / 讲** × 作用域（单频道 / 全服对应类型）。

## 4.2 谁可施加

| 角色 | 范围 |
|------|------|
| 系统管理员 | 任意 |
| 服务器管理员 | 层级允许下本服 |
| 协管 | **窄权限（可配）**：默认仅 **本语音频道禁说 / 抱下** 等 |

## 4.3 保护对象

| 规则 | 定稿 |
|------|------|
| 所有者 | **不可** 被限制（系统管例外） |
| 角色 position | **不可** 限制 position ≥ 自己的成员（系统管例外） |

## 4.4 与 RBAC

**Restriction 只收紧**，优先于 RBAC 的允许位。

## 4.5 类型

| 类型 | 定稿 |
|------|------|
| 临时限制 | Restriction **带 `expires_at`** |
| 频道级 ban | **无到期** 的频道 ban（仍用 Restriction 或专用记录，语义保留） |
| 全服踢出 | 仍用 **`Ban Member`**，不与 Restriction 混用 |

## 4.6 展示

| 观众 | 展示 |
|------|------|
| 当事人 | **原因 + 到期时间** |
| 其他人 | 可仅显示 **「该用户被限制」** |

### 专项 4 注意

1. 「禁看」→ API **404** + Gateway 不推。  
2. 与 `server_mute`、舞台自动禁说：**来源字段区分**，避免管理 UI 混乱。  
3. 全服禁听时批量 disconnect/改 caps。

# 专项 5：语音包 · 文字 · 屏幕共享

## 5A 入场语音包

| 编号 | 定稿 |
|------|------|
| 5A.1 触发 | **进服首次出现** / **进指定语音频** 可配；**默认不要**「每次切频都放」 |
| 5A.1b 频道开关 | **每个子频道管理员** 可配置本频道 **是否允许播放** 入场语音包 |
| 5A.2 谁听到 | 默认 **同语音频道**；可配 **全服在线**（谨慎） |
| 5A.3 实现 | **客户端拉短音频 URL 本地播放**（不经 SFU 长轨道） |
| 5A.4 权限 | **配置包**：服管；**使用稀有包**：角色/资产；频道开关见 5A.1b |

## 5B 文字频道

| 编号 | 定稿 |
|------|------|
| 5B.1 存储 | **PostgreSQL** 消息主存 + **对象存储** 附件 |
| 5B.2 历史 | 具备 **`READ_MESSAGE_HISTORY`** 才可拉取历史 |
| 5B.3 附件 | **允许各类附件**；**预览** 仅：**PDF、音频、视频、图片** |
| 5B.3b 大小 | **单文件上限** 由 **系统管理员按每个服务器** 调整 |
| 5B.4 编辑 | 允许编辑文本；**完整编辑历史审计**；UI 显示 **已编辑 + 编辑次数** |
| 5B.5 搜索 | **支持全系统搜索**（跨服/全局检索能力；权限上仍只能命中调用者可见内容） |

### 5B 注意

1. **全系统搜索** 工程量大：权限过滤必须在检索层强制（防越权命中 404 频道）。  
2. 建议索引组件（如 OpenSearch/Meilisearch/Postgres FTS）在实现专项另定；**产品要求已定：要做全系统搜索**。  
3. 编辑历史表不可被客户端篡改；次数以服务端为准。  
4. 附件预览与「可上传任意类型」分离：不能预览的提供下载。

## 5C 屏幕共享

| 编号 | 定稿 |
|------|------|
| 5C.1 权限位 | 保留 **`STREAM`**、**`STREAM_QUALITY`** |
| 5C.2 大房/舞台 | **仅台上可共享**，听众不可 |
| 5C.3 路径 | **默认走媒体服务器（SFU）中转**，不走客户端 Mesh  
| | ⚠️ **不是** Newt-Server 控制面转发 RTP；控制面仍只编排 |
| 5C.3b 路数 | **不设固定全局硬顶**；**系统管理员** 可按资源占用 **动态设置每个服务器允许的同时屏幕共享数量**；并有 **按负载动态下调最大值的开关** |
| 5C.4 Token | caps 含 **`publish_screen`**；系统管可配置相关展示策略/自定义显示内容（产品配置项） |

### 5C 注意

1. 「动态无限」在物理上仍受节点带宽/CPU 约束；动态限额是 **控制面保护**，不是魔法。  
2. 多节点级联下屏幕流中继成本远高于音频，调度应 **优先让共享者与多数观众同节点或近锚点**。  
3. 与台上硬顶 50 叠加时，需防止「50 台上 + 多路 1080p」打爆池；动态限额与服级配额联动。

## 衍生实现专项（下一波可开设计文）

按依赖顺序建议：

1. **逻辑语音房多节点级联协议**（树/星、anchor 选举、故障切根）
