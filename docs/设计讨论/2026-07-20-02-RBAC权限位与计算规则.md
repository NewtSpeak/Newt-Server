## 1. 目标

1. 给出 **可编码** 的权限位集合（服务器级 + 文本/语音频道相关）。
2. 定义 **最终权限** 的计算顺序与短路规则。
3. 定义频道覆盖（Overwrite）的语义。
4. 约定权限变更后如何影响文本操作与语音会话（与后续信令文档衔接）。

---

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| **服务器 (Guild)** | 独立权限域；跨服权限互不影响 |
| **角色 (Role)** | 服务器内权限模板；含 `position`（层级）、`permissions`（位掩码）、`hoist`/`mentionable` 等展示字段（首期可简） |
| **@everyone** | 特殊角色，自动赋予全部成员；`position` 最低；作为权限基线 |
| **成员 (Member)** | 用户在某服务器内的身份；可绑定多个角色 |
| **频道 (Channel)** | 文本 / 语音等；可有独立 **权限覆盖** |
| **覆盖 (Overwrite)** | 针对「角色」或「成员」在某频道上的 `allow` / `deny` 位掩码 |
| **最终权限** | 对「某成员 × 某作用域（服务器或频道）」算出的有效位掩码 |

存储建议：权限用 **64 位整数位掩码**（或 `uint64` / 两个 `uint32`）；预留扩展位。首期位编号从 0 起，**未列出的 bit 禁止使用**。

## 3. 权限位表

### 3.1 通用约定

- 名称采用 `SCREAMING_SNAKE`，API/存储可用相同字符串或数值枚举。
- **`VIEW_CHANNEL`**：看不见则多数频道操作失败（见计算后校验）。
- **管理员短路**：拥有 `ADMINISTRATOR` 时，在服务器内视为拥有全部权限（频道拒绝覆盖 **不** 限制管理员——与 Discord 一致，便于运维；若产品要「管理员也可被频道拒绝」，单独立项，本草案 **不采用**）。

|-----|------|--------|------|

> 其余位可先定义进枚举，逻辑返回「功能未开放」。

### 3.3 默认权限建议

| 角色 | 建议默认位（概念） |
|------|-------------------|
| **@everyone** | `VIEW_CHANNEL` + `SEND_MESSAGES` + `READ_MESSAGE_HISTORY` + `CONNECT` + `SPEAK` + `CHANGE_NICKNAME` + `ADD_REACTIONS` + `USE_VAD`（可按产品收紧） |
| **服务器所有者** | 隐式拥有全部权限（不依赖角色位；或绑定不可移除的最高角色） |
| **新建自定义角色** | 权限默认 `0`，由管理员勾选 |

创建服务器时：创建所有者成员 + `@everyone` + 可选「管理员」角色模板。

## 4. 角色层级（Role Hierarchy）

用于限制「谁能改谁的角色 / 踢谁 / 改谁的权限」。

| 规则 | 说明 |
|------|------|
| `position` 为整数，越大越高 | 同 position 时以 `role_id` 稳定排序（实现自定） |
| `@everyone` 恒为最低 | `position = 0` 固定 |
| 所有者高于一切 | 不受 position 限制 |
| 可管理的角色 | 操作者最高角色 position **严格大于** 目标角色 |
| 可踢/禁的成员 | 操作者最高角色 position **严格大于** 目标成员最高角色 |
| `MANAGE_ROLES` 可分配的权限位 | 不得超过操作者自身最终服务器权限（防提权） |

## 5. 权限计算算法

### 5.1 输入

- `member`：含 `user_id`、是否 `owner`、角色列表
- `guild`：角色定义、`@everyone` 权限
- `channel`（可选）：若计算频道权限则传入 + 该频道的 overwrites

### 5.2 伪代码（服务器级基线）

```text
function base_permissions(member, guild) -> bits:
    if member is guild.owner:
        return ALL_PERMISSIONS

    bits = guild.@everyone.permissions
    for role in member.roles:
        bits |= role.permissions

    if bits has ADMINISTRATOR:
        return ALL_PERMISSIONS

    return bits
```

### 5.3 伪代码（频道最终权限）

与 Discord 对齐的经典顺序：

```text
function channel_permissions(member, guild, channel) -> bits:
    base = base_permissions(member, guild)
    if base has ADMINISTRATOR:
        return ALL_PERMISSIONS

    // 1) @everyone 频道覆盖
    ow_everyone = overwrite(channel, type=role, id=@everyone)
    if ow_everyone:
        base &= ~ow_everyone.deny
        base |= ow_everyone.allow

    // 2) 成员拥有的各角色覆盖（先合并所有 deny，再合并所有 allow）
    allow = 0
    deny = 0
    for role in member.roles:
        ow = overwrite(channel, type=role, id=role.id)
        if ow:
            allow |= ow.allow
            deny  |= ow.deny
    base &= ~deny
    base |= allow

    // 3) 成员专属覆盖（优先级最高）
    ow_member = overwrite(channel, type=member, id=member.user_id)
    if ow_member:
        base &= ~ow_member.deny
        base |= ow_member.allow

    return base
```

### 5.4 校验辅助

```text
function can(member, channel_or_guild, permission) -> bool:
    bits = channel ? channel_permissions(...) : base_permissions(...)
    return (bits & permission) == permission

// 进入语音频道
need VIEW_CHANNEL | CONNECT
// 发布音频
need SPEAK  （且未被服务器 mute / 频道 mute）
// 发文本
need VIEW_CHANNEL | SEND_MESSAGES
// 拉历史
need VIEW_CHANNEL | READ_MESSAGE_HISTORY
```

**隐含规则：**

| 规则 | 说明 |
|------|------|
| 无 `VIEW_CHANNEL` | 频道对用户不可见；API **404**（防扫频，已定稿） |
| 有 `CONNECT` 无 `SPEAK` | 可进房听，不可发布音频（旁听 / 听讲模式听众） |
| 服务器 Mute | 即使有 `SPEAK` 也不可发布；由成员状态字段表示，**不是** 权限位 |
| 服务器 Deafen | 不可接收；成员状态字段 |
| **Restriction（多维限制）** | 可单独禁止：某文字频 看/说、某语音频 听/说、或全服文字/语音 看·听/说；见 [06 §6](./2026-07-20-06-评审定稿决议.md) |

### 5.5 Restriction 与成员状态对权限的叠加

在得到 `bits` 之后应用 **Restriction**（只收紧，不放宽）：

```text
for r in active_restrictions(member, guild, channel):
    if r.denies view_text for this text channel or guild-all-text:
        bits &= ~VIEW_CHANNEL; bits &= ~READ_MESSAGE_HISTORY; ...
    if r.denies send_text:  bits &= ~SEND_MESSAGES; bits &= ~ADD_REACTIONS; ...
    if r.denies listen_voice for this voice channel or guild-all-voice:
        bits &= ~CONNECT  // 或进房后强制不可 subscribe，语义「不能听」
    if r.denies speak_voice: bits &= ~SPEAK
```

服务器 mute/deafen **不改权限位**，进房后 SFU 能力由 Server 写入 media token / 控制指令。  
完整矩阵与模型见 06 决议；本节替换原「单一 timeout」草案。

## 6. 覆盖（Overwrite）数据模型

```text
ChannelOverwrite {
  channel_id: ID
  type: enum { ROLE = 0, MEMBER = 1 }
  target_id: ID          // role_id 或 user_id
  allow: uint64
  deny: uint64
}
```

约束：

- 同一 `(channel_id, type, target_id)` 唯一。
- 同一 bit **不应** 同时出现在 allow 与 deny；若发生，**deny 优先**（写入时校验拒绝，或计算时先 deny 后 allow——与上文算法「先 deny 再 allow」在步骤内一致；成员覆盖步骤内也是先 deny 后 allow）。
- 删除覆盖 = 恢复继承。

## 7. 与语音 / SFU 的映射（能力投影）

Server 计算频道权限后，映射为 media token 最小能力（SFU 不理解业务位名）：

| 业务条件 | Media capability |
|----------|------------------|
| `VIEW_CHANNEL` + `CONNECT` | `join` |
| `SPEAK` 且未 server-mute 且未 timeout 禁说 | `publish_audio` |
| `STREAM` 且产品开启 | `publish_video` / `publish_screen` |
| 默认同房 | `subscribe_audio`（听）— 有 `CONNECT` 即给；deafen 时 Server 不发或发后立刻限制 |
| `PRIORITY_SPEAKER` | `priority_speaker`（可选） |
| `MUTE_MEMBERS` 等 | **不** 进 token；管理动作走 Server API → 控制通道 |

权限被撤后的实时生效见《进房信令时序》文档。

## 8. API 行为约定（Server）

| 操作 | 所需权限（最低） |
|------|------------------|
| 列出可见频道 | 隐式：每频道 `VIEW_CHANNEL` 过滤 |
| 发送消息 | 频道 `SEND_MESSAGES` |
| 删除他人消息 | `MANAGE_MESSAGES` |
| 创建频道 | 服务器 `MANAGE_CHANNELS` |
| 编辑频道覆盖 | `MANAGE_ROLES` 或 `MANAGE_CHANNELS`（二选一定稿；建议需 `MANAGE_ROLES` 且位不超自身） |
| 连接语音 | `CONNECT`（+ `VIEW_CHANNEL`） |
| 服务器静音他人 | `MUTE_MEMBERS` + 层级允许 |
| 移动成员 | `MOVE_MEMBERS` |

所有检查在 **Owl-Server** 完成；客户端展示用权限可下发缓存，**不可信**。

## 9. 缓存与失效

| 策略 | 说明 |
|------|------|
| 计算可缓存 | key: `(guild_id, user_id, channel_id?)` → bits |
| 失效触发 | 角色权限变更、成员角色变更、覆盖变更、所有者转让、timeout/mute 状态变更 |
| 推送 | 通过 Gateway/WS 发 `PERMISSIONS_UPDATE` 或让客户端重拉 `GET /guilds/:id/members/@me` |

## 10. 本轮结论

| # | 结论 |
|---|------|
| 1 | 采用 **uint64 位掩码 + 角色并集 + 频道覆盖** 模型 |
| 2 | 计算顺序：所有者/管理员短路 → `@everyone` → 角色覆盖（deny 合再 allow 合）→ 成员覆盖 |
| 3 | `ADMINISTRATOR` 与所有者绕过频道 deny |
| 4 | 角色层级约束踢人/改角色/防提权 |
| 5 | 服务器 mute/deafen 用 **成员状态**，不进权限位；timeout 在计算后 mask |
| 6 | SFU 仅收 **投影后的 capabilities**，不解释完整 RBAC |
| 7 | P0 权限子集已列出，其余位预留 |

## 11. 评审定稿修订（对齐 06）

| 项 | 定稿 |
|----|------|
| 无 `VIEW_CHANNEL` | API **404**，防扫频 |
| `ADMINISTRATOR` | **无视** 频道 deny |
| `@everyone` 默认 | 可看、可发消息、可连麦、可说话 |
| 超时/禁言 | **废止单一粗粒度 timeout**；改为多维 **Restriction**（文字看/说、语音听/说 × 单频道或全服）见 [06 §6](./2026-07-20-06-评审定稿决议.md) |
| 权限权威层级 | **系统管理员 > 服务器管理员 > 子频道覆盖/协管** |
| 改频道覆盖 | 系统管任意；服管在层级与「不超自身权限」下可覆盖本服；具体权限节点可配置 |
| 自定义角色 | 系统管 + 服管可定义角色、权限节点与 **按子频道访问范围** |
| 舞台相关 | 预留/启用 `REQUEST_TO_SPEAK`；协管与「抱麦」需独立权限节点（专项补表） |
| `STREAM` | **后期必做**，位与 caps **预留**，首期逻辑可未实现 |

### 11.1 Restriction 叠加（替换原 §5.5 单一 timeout 叙述）

```text
bits = channel_permissions(...)  // 含管理员短路
bits = apply_restrictions(bits, member, channel, guild)  // 多维限制，只做收紧
return bits
```

Restriction 维度见 06 §6.1；数据模型见 06 §6.3。
