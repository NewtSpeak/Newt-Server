## 1. 目标与范围

补齐 NewtSpeak 目前完全缺失的**服务器外（guild-free）社交层**，四个子系统一次定稿：

1. **好友关系（Relationships）**：请求 / 接受 / 忽略 / 取消 / 删除 / 屏蔽，Discord 语义。
2. **私信（DM / Group DM）**：1:1 私信、群组私信、消息请求箱，消息面 100% 复用 13 号文档。
3. **隐私设置（Privacy Settings）**：谁能加我好友、谁能私信我、消息请求过滤、资料可见性；账号级 + 每服覆盖（17 FR-18）。
4. **系统通知（System Notifications）**：站内通知收件箱 + 官方只读系统私信通道——此项为 Newt-Desktop 19 未覆盖的**新增子系统**，客户端需求另立 Newt-Desktop 21。

**不在本次范围**（与 19 §1.2/§6.5 一致）：DM 语音通话（P2，需 SFU room 脱离 guild，另立专项；届时端侧降噪偏好按 Newt-Desktop 20 §1.5-R7 预决议复用同一套 `nsModel`/`localNs`）、好友分组、E2EE、数据导出（P2）。

## 2. 关系模型（BK）

### 2.1 存储（BK.1）

采用 19 §3.1 的**单行投影**方案：

```text
relationships (
  id, user_id, target_user_id,
  type,           -- friend | pending_outgoing | blocked（incoming 由对端 pending_outgoing 投影）
  nickname,       -- 好友备注名，仅本人可见，≤32 字符，仅 friend 可设
  created_at, updated_at,
  UNIQUE(user_id, target_user_id)
)
```

- `friend` 成对写入（双行，事务内）；`pending` 只存发起方一行；`blocked` 只存屏蔽方一行。
- 查询「我收到的请求」= `WHERE target_user_id = me AND type = 'pending_outgoing'`。

### 2.2 规则（BK.2–BK.7）

| # | 规则 |
|---|------|
| **BK.2** | 屏蔽压倒一切：写 `blocked` 时事务内清除双方 `friend` 行与相关 `pending` 行；对端**不收到任何「被屏蔽」提示**（其视角为好友/请求消失）。解除屏蔽回到 `none`，**不**自动恢复好友（19 §3.1）。 |
| **BK.3** | 双向各自 `blocked` 允许并存，互不感知。 |
| **BK.4** | 上限：好友 ≤ **1000**；未决请求（收+发合计）≤ **200**；屏蔽 ≤ **1000**。超限返回 `RELATIONSHIP_LIMIT`。 |
| **BK.5** | 互发即好友：A→B 已有 `pending_outgoing` 时 B 再请求 A，直接升级双向 `friend`（19 §11「同时互发」）。 |
| **BK.6** | 忽略（拒绝）请求：删除对端 `pending_outgoing` 行，**不通知**发起方（发起方不知晓，仍可取消；对标 Discord 静默忽略）。接受则双端推 `RELATIONSHIP_ADD(friend)`。 |
| **BK.7** | 账号注销：其全部 relationship 行删除，对端收 `RELATIONSHIP_REMOVE`；历史 DM 频道保留，显示「已注销用户」占位（19 §11）。 |

## 3. 好友请求（BL）

| # | 规则 |
|---|------|
| **BL.1** | 发起载荷 `{username}` 或 `{user_id}`：用户名为**全局唯一标识、无识别码**（Newt-Desktop 01 FR-12；19 FR-F01）。 |
| **BL.2** | 错误暴露边界（19 FR-F03 定稿）：用户名不存在 → **允许**返回 404 `USER_NOT_FOUND`；目标屏蔽了我 / 隐私设置拒绝 → 统一 403 `PRIVACY_DENIED`，**同形不可区分**（防探测）。 |

| **BL.5** | 送达：目标在线端推 `RELATIONSHIP_ADD(pending_incoming 投影)` + 写收件箱通知（BQ，type=`FRIEND_REQUEST`）。 |

## 4. 隐私设置（BM）

### 4.1 账号级字段（BM.1）

独立表 `privacy_settings(user_id, ...)`，字段与取值**照抄 19 §3.2 定稿**（服务端为裁决权威，READY 下发镜像）：

| 字段 | 取值 | 默认（19 §4.2 安全默认） |
|------|------|--------------------------|
| `friend_request_from` | `everyone` / `mutual_friends` / `mutual_guilds` / `nobody` | `mutual_guilds` |
| `dm_from` | `everyone` / `friends` / `mutual_guilds` / `nobody` | `friends` |
| `message_request_filter` | bool（非好友一律先进请求箱） | `true` |
| `show_mutual_guilds` | bool | `true` |
| `public_profile_to_non_friends` | bool（bio/banner 对非好友可见；邮箱永不暴露） | `true` |
| `show_activity_to` | `everyone` / `friends` / `nobody`（默认 `friends`） | 见 **18** 号活动状态专项 M1；不再是空占位 |

- **BM.2** 每服覆盖 `allow_dm`（即 17 号「允许本服成员私信」，默认 `true`）：**服务端一等字段**，独立存储 `guild_member_privacy(user_id, guild_id, allow_dm)`，**不放入**客户端不透明 `user_settings` JSON——裁决路径上的字段必须服务端权威且可索引（决议 D7，见 §13）。读写走 BR.1 专用端点；`GET /users/@me/privacy` 响应附 `guild_overrides` 映射；变更推 `USER_SETTINGS_UPDATE(privacy)` 跨端同步。语义 = 关闭后**仅因共同在该服**获得的新私信资格失效，好友 DM 与既有会话不受影响（17 FR-18、19 §3.2）。退服/被踢时服务端删除该行。
- **BM.3** 修改隐私**不回溯**已建立会话（19 §11），仅影响新发起；例外：`blocked` 实时切断（BP）。
- **BM.4** 变更推本人多端 `USER_SETTINGS_UPDATE(privacy)`；多端冲突以最后 PATCH 为准（19 §11）。

### 4.2 裁决管线（BM.5，= 19 §4.3/§4.4 的服务端权威实现）

**好友请求**（发起方 S → 接收方 R）：

```
1. 任一方 blocked 对方            → 403 PRIVACY_DENIED（同形）
2. 已 friend / 已 pending         → 409 冲突（幂等场景除外）
3. R.friend_request_from:
   everyone → 通过 | mutual_friends → 需共同好友 | mutual_guilds → 需共同服 | nobody → 403 同形
```

**新私信**（创建或向 R 侧 hidden 会话投递新消息）：

```
1. 任一方 blocked 对方                        → 403 PRIVACY_DENIED
2. 已是好友                                   → 放行（直接会话）
3. 已存在非 message_request 的可见 DM         → 放行（继续发送）
4. R.dm_from: nobody → 拒 | friends → 拒（非好友）| mutual_guilds/everyone → 继续
5. 资格依赖共同服时：取共同服集合 G，需存在 g∈G 使 R.guild_overrides[g].allow_dm ≠ false（BM.2 表）
6. R.message_request_filter && 非好友          → 落消息请求箱（BO）
   否则                                       → 直接会话
7. dm_from=everyone 且无共同服（纯用户名私信）→ 强制走消息请求箱（19 §4.4 第 7 步采纳其建议）
```

- **BM.6** 「共同服务器」实时查成员表，缓存 ≤60s（防被踢后长期可达）；管线结果不落库。

## 5. DM 频道模型（BN）

### 5.1 类型与结构（BN.1）

`ChannelType` 扩展为 `TEXT | VOICE | CATEGORY | DM | GROUP_DM`（19 §3.3）；`guild_id = NULL`。

| 维度 | `DM` | `GROUP_DM` |
|------|------|------------|
| 参与者 | 恰好 2 人；`(min_id,max_id)` 全局唯一索引，get-or-create 幂等 | 2–**10** 人（上限可配） |
| 名称/图标 | 无（客户端显示对方） | 可选自定义名；无自定义图标时客户端拼头像 |
| 治理 | — | **无群主**（19 FR-G02 建议采纳，定稿见 §13-D3）：任何成员可邀请（仅可拉**自己的好友**）、任何成员可改名；**无踢人**，只有主动离开；人满拒绝邀请 |

参与者表照抄 19 §3.3：

```text
channel_recipients (
  channel_id, user_id, joined_at,
  hidden,                -- 关闭私信：列表隐藏，历史保留；对方新消息或本人打开时置回 false
  last_read_message_id,  -- read state 与 guild 频道同水位线机制
  message_request,       -- true：仍在请求箱
  muted, muted_until,
  UNIQUE(channel_id, user_id)
)
```

### 5.2 规则（BN.2–BN.6）

| # | 规则 |
|---|------|
| **BN.2** | DM/GROUP_DM **不参与 RBAC**（02 权限位全部不适用）：可见性 = 在 `channel_recipients` 中且（对请求箱/隐藏有相应视图规则），仅此一条。 |
| **BN.3** | 消息面完全复用 13 号：消息表/雪花 ID（AP.1）、`POST/GET /channels/{id}/messages`（AR.1/2）、附件预签名（AT.1–2）、编辑/删除/回复/反应/置顶/typing 语义不变。差异仅：① 删除权限=作者本人；② DM 内 @ 仅限参与者，无 @everyone/@role（19 FR-D08）；③ 附件走平台默认用户 DM 限额，不吃服级上限（19 FR-D10）。 |
| **BN.4** | 搜索：接 13 号搜索体系加 `in:dm` 范围，索引按 channel 隔离，仅参与者可命中（19 FR-D11、§11）。 |
| **BN.5** | GROUP_DM 系统灰条消息（复用消息表 `message.type`）：`SYSTEM_RECIPIENT_ADD` / `SYSTEM_RECIPIENT_REMOVE` / `SYSTEM_CHANNEL_NAME_CHANGE`（19 FR-G03）。 |
| **BN.6** | GROUP_DM 全员离开 → 频道软删+GC（19 §11）；1:1 永不删除（hidden 机制代替）。 |

## 6. 消息请求（BO）

| # | 规则 |
|---|------|
| **BO.1** | 按 BM.5 管线落箱：创建/复用 DM，接收方行 `message_request=true`；接收方视图入「消息请求」，**不产生系统通知与声音**，仅静默计数（19 §3.4/FR-D14）。 |
| **BO.2** | 接受：`PATCH recipients/@me {message_request:false}`；接收方**回复即视同接受**。拒绝：置 `hidden=true`（可组合 block）。发起方对「已读未接受」**零感知**（19 §3.4）。 |
| **BO.3** | 好友关系建立时，存量请求箱会话自动转正（双端推 `CHANNEL_UPDATE`）。 |
| **BO.4** | 接受前发起方限发 **5 条/天/会话**（19 §8.4 采纳），超出返回 429 `MESSAGE_REQUEST_LIMIT`。 |

## 7. 屏蔽语义（BP）

| # | 规则 |
|---|------|
| **BP.1** | 我屏蔽 X 即刻生效：X 的新好友请求/新 DM/群邀请全部按 BM.5 第 1 步拒绝；X 向既有 1:1 DM 发消息 → 403 `PRIVACY_DENIED`（同形），**服务端不投递**（19 §10.5/§11「新消息不投递」定稿为强制而非可选）。 |
| **BP.2** | 共享 guild 频道内：服务端**照常投递** X 的消息与事件，**不做剪裁**（避免 read state/搜索计数分叉）；客户端依据本地 `relationships.blocked` 集合折叠渲染「已屏蔽的消息」，且不产生未读/提及/通知（客户端职责，见 19 FR-P06 与 Newt-Desktop 15）。 |
| **BP.3** | GROUP_DM 中双方可共存（各自客户端折叠对方）；被屏蔽者不能把屏蔽者拉进新群（拉人也走 BM.5 第 1 步）。 |
| **BP.4** | 屏蔽/解除推**仅屏蔽方**多端 `RELATIONSHIP_ADD(blocked)/REMOVE`；对端只收到好友/请求消失的 `RELATIONSHIP_REMOVE`（不含原因）。 |

## 8. 系统通知（BQ）——新增子系统

### 8.1 收件箱（BQ.1）

独立存储 `notifications(id 雪花, user_id, type, payload JSON, created_at, read_at?)`，与消息表分离：

| type | 触发 | payload 要点 |
|------|------|--------------|
| `FRIEND_REQUEST` | 收到好友请求（BL.5） | 请求方摘要 |
| `FRIEND_ACCEPT` | 请求被接受（19 FR-F18 的数据源） | 接受方摘要 |
| `GUILD_MODERATION` | 被处罚/被踢/被封禁：Restriction 生效时当事人可见 reason/expires（12 AM.1） | guild、动作、reason、expires |
| `SYSTEM_ANNOUNCE` | 运营公告/版本/维护（管理后台发起，全员或定向） | 标题、正文（Markdown 子集）、跳转链接 |
| `ACCOUNT_SECURITY` | 新设备登录、密码/邮箱变更（接 Newt-Desktop 01） | 设备/IP 摘要 |

- **BQ.2** 未读数 = `read_at IS NULL` 计数，随 READY 下发；ack 走水位线（BR.4）。
- **BQ.3** 已读通知保留 **90 天**；`SYSTEM_ANNOUNCE` 支持撤回（推 `NOTIFICATION_DELETE`）。
- **BQ.4** **官方系统私信**：固定系统账号「NewtSpeak 官方」，实现为 `DM` 频道特例 `system=true`：不可屏蔽、不可关闭、用户 `POST messages` 返回 403 `SYSTEM_CHANNEL_READONLY`；重大通知（封禁申诉结果等）双落（收件箱 + 系统 DM）。
- **BQ.5** 收件箱事件是否升级为桌面系统通知由客户端按 Newt-Desktop 15 的通知层级/勿扰决策，服务端只推事实（好友请求默认弹、公告默认仅角标等策略见 Newt-Desktop 21）。

## 9. REST API（BR）

路径、命名**以 19 §8 建议为基线定稿**；鉴权、限流头、错误体与 13 号一致。

### 9.1 隐私与关系（BR.1）

```
GET    /users/@me/privacy                             # 响应含 guild_overrides: {guild_id: {allow_dm}}
PATCH  /users/@me/privacy                             # 部分更新（BM.1 字段）
PUT    /users/@me/guilds/{guild_id}/privacy           # body {allow_dm} 每服覆盖（BM.2，服务端一等字段）
GET    /users/@me/relationships                       # friend + pending(双向投影) + blocked
POST   /users/@me/relationships                       # {username} 或 {user_id} 发请求（BL）
PUT    /users/@me/relationships/{user_id}             # {type:"friend"} 接受 | {type:"blocked"} 屏蔽
PATCH  /users/@me/relationships/{user_id}             # {nickname} 备注
DELETE /users/@me/relationships/{user_id}             # 语境化：删好友/取消/忽略/解除屏蔽
```

（服级 `allow_dm` 使用上表专用端点，**不**走 17 号不透明 settings JSON——见 BM.2/§13-D7。）

### 9.2 私信频道（BR.2）

```
GET    /users/@me/channels                            # DM+GROUP_DM 列表（recipient 摘要、last_message），分页
POST   /users/@me/channels                            # {recipient_id} → DM get-or-create；{recipients:[]} → GROUP_DM
PATCH  /channels/{id}                                 # GROUP_DM 改名（任何成员）
PATCH  /channels/{id}/recipients/@me                  # {hidden} 关闭 | {message_request:false} 接受请求
PUT    /channels/{id}/recipients/{user_id}            # GROUP_DM 邀请（仅可邀自己的好友）
DELETE /channels/{id}/recipients/@me                  # 离开群组（无踢人，§13-D3）
```

消息/附件/反应/置顶/已读：沿用 13 号 `POST/GET /channels/{id}/messages`、`POST /channels/{id}/ack` 等，**零新增**。

### 9.3 消息请求视图（BR.3）

请求箱不单独建资源：`GET /users/@me/channels?filter=message_request` 返回 pending 会话；接受/拒绝走 BR.2 的 `recipients/@me`（与 19 §8.2 一致）。

### 9.4 通知收件箱（BR.4）

```
GET    /users/@me/notifications?before=&limit=
POST   /users/@me/notifications/ack                   # {last_read_id} 水位线已读
DELETE /users/@me/notifications/{id}
```

## 10. Gateway 事件（BS）

采纳 19 §8.3：**复用既有 `CHANNEL_*` 事件族**，不另造 `DM_CHANNEL_*` 命名空间。

| 事件 | 触发 |
|------|------|
| `RELATIONSHIP_ADD` / `UPDATE` / `REMOVE` | 关系迁移（BK）；UPDATE 用于备注等 |
| `CHANNEL_CREATE` / `UPDATE` / `DELETE` | DM/GROUP_DM 对某用户可见/变更/不可见（含 hidden 重开、请求转正、改名、recipient 变化；负载含 `recipients[]` 与 `message_request` 标记） |
| `MESSAGE_CREATE` 等消息族 | 复用 13 AR.5 原样，`guild_id=null`，仅 recipients 收到 |
| `NOTIFICATION_CREATE` / `DELETE` | 收件箱新增/撤回（BQ） |
| `USER_SETTINGS_UPDATE` | 隐私设置变更（BM.4） |

- **BS.1** READY 快照扩展（19 §8.3 基线 + 通知）：

```jsonc
{
  "relationships": [ ... ],
  "private_channels": [ /* DM/GROUP_DM 摘要，含 last_message_id、message_request、hidden */ ],
  "privacy": { ... },
  "notification_unread_count": 3
}
```

- **BS.2** DM read state 与 guild 频道同一套水位线协议（补上 Newt-Desktop 14 §7-8 / 15 的服务端待补充项）。
- **BS.3** presence：好友 presence 快照随 READY relationships 下发，之后 `PRESENCE_UPDATE` 按可见性推送（19 FR-F14–F16；隐身对好友显示离线，01 FR-20）。

## 11. 频控与滥用防护（BU）

采纳 19 §8.4 并补全：

| # | 规则 |
|---|------|
| **BU.1** | 好友请求：**≤20 次/小时/用户**；对同一目标被忽略/取消后 **24h 冷却**。 |

| **BU.5** | DM 内容与附件违禁策略与公屏一致（19 §8.4）。 |

## 12. 错误码（BV）与观测（BW）

| 逻辑码 | HTTP | 场景 |
|--------|------|------|
| `USER_NOT_FOUND` | 404 | 用户名不存在（**允许**精确提示，BL.2） |
| `PRIVACY_DENIED` | 403 | 被屏蔽/隐私拒绝**同形**（BL.2/BP.1） |
| `RELATIONSHIP_LIMIT` | 400 | BK.4 上限 |
| `RELATIONSHIP_STATE_CONFLICT` | 409 | 状态机非法迁移 |
| `GROUP_DM_FULL` | 400 | 成员 >10 |
| `MESSAGE_REQUEST_LIMIT` | 429 | BO.4 |
| `SYSTEM_CHANNEL_READONLY` | 403 | 向官方系统 DM 发消息（BQ.4） |

- **BW.1** 指标：请求发起/接受率、请求箱接受/拒绝/举报率、屏蔽次数、`NOTIFICATION_CREATE` 送达 P99、READY relationships 尺寸分布、关系变更端到端延迟（19 §15 要求 ≤500ms）。
- **BW.2** 审计与隐私红线：屏蔽/举报/公告下发走 12 号审计管道；**系统管理员无特权读取他人私信**（19 §11），合规调取须走独立审计工具。
- **BW.3** 数据合规：注销即删关系与匿名化 DM 消息（与 01 账号删除策略一致）；导出 P2。
